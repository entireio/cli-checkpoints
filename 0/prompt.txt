### Low finding

**Location:** `cmd/entire/cli/explain_summary_provider.go:82-97`

The `external_agents` grant can still be minted with no human in the loop, which is in tension with the invariant this PR establishes.

The comment at lines 82-86 says "selecting it in the picker is when external_agents flips on (handled by `persistSummaryProviderSelection`)". But the non-interactive branches never reach a picker: with one candidate line 94 auto-selects it, and with several and no TTY line 97 auto-selects `candidates[0]`. Either can be an external agent, and `autoSelectSummaryProvider` → `persistSummaryProviderSelection` then writes `external_agents: true` into `settings.local.json`. That grant is not scoped to the chosen provider — it enables discovery of every `entire-agent-*` binary on `$PATH` from then on.

`runSetupFlow` under `--yes` (`setup.go:422` plus `selectAllAgents`) is the same shape: full sweep, then grant, with no human choosing.

Both are pre-existing, and the binary must already be on the user's absolute `$PATH`, so this is not a claim of a new hole. Raising it because this PR is what turns "external_agents is only ever developer-chosen" into a documented rule — so it wants either a fix (don't persist the grant on a non-interactive auto-select) or one line saying the auto-select path is an accepted exception.

No patch attached: which way this goes is a product call, not a mechanical fix.

### Low finding

**Location:** `cmd/entire/cli/setup_external_agents.go:52-62`

`enableExternalAgentsLocally` reports success for a write that cannot have taken effect, reproducing the exact symptom commit 51d062a34 fixed, by a second route.

When `.entire/settings.local.json` is **tracked**, `loadMergedSettings` drops the whole local layer, so the key this function just wrote is never read. The grant is inert. And because `s.ExternalAgents` is then false by the time the gate runs, `enforceExternalAgentsTrust` returns at `external_agents_trust.go:44` and records **no** `externalAgentsRejection` — so neither `entire status`'s new line (`status.go:145`) nor `reportExternalAgentsRejection` says anything about `external_agents`. The user sees `externalAgentsAutoEnabledNotice` ("external agents are now enabled for the rest of Entire too", `setup.go:67`) and the only clue is the generic local-layer rejection line.

Same class as the omitempty bug: told enabled, next load does not honor it.

Fix shape: have `enableExternalAgentsLocally` re-`settings.Load` after the write and report whether the grant verified — `(effective bool, err error)`, or a sentinel the callers can `errors.Is` — and have the four grant sites (`setup.go:273`, `:669`, `:1345`, `:2039`) print the `git rm --cached` remedy instead of the notice when it did not. Not a hard error: one committed file must not fail `entire enable`.

No patch attached: the signature change touches `setup.go` as well, and a finding patch is limited to one file.
