`configureBranchProtected` only queries GitHub's repository-ruleset endpoint (`/rules/branches/{branch}`), which returns effective ruleset rules but never reflects classic branch protection (`/branches/{branch}/protection`). A branch protected only via classic protection (still the common case for many repos) will be reported as unprotected, so `entire configure` can offer/choose "Save — push to `branch`" and create a local commit directly on the user's branch. The subsequent `git push` will then be rejected by GitHub, leaving an unpushed, uncommitted-feeling commit stranded on the user's checked-out branch that they must clean up manually.
