`ensureConfigureLogin` sends the login bearer via `deps.fetchProfile(ctx, target.coreURL, target.token)` without ever calling `api.RequireSecureURL(target.coreURL)` first. Every other call site that resolves a target through `resolveAuthStatusTarget` (`auth.go`, `logout.go`, `api_cmd.go`, `repo_mirror_create_wizard.go`, `login.go`) guards the bearer with this check before sending it; this new path (both here and the second call at line 285) skips it, so a misconfigured/downgraded `coreURL` (e.g. plain HTTP) would leak the token where the rest of the codebase treats that as unacceptable.
