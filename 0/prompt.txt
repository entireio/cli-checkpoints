Clearing an untrusted ReviewConfig.Prompt makes prompt-only workers look unset. IsZero treats a config with only a now-empty prompt as empty, and nonZeroAgentConfigs then drops those workers. A committed Pi-style {"pi":{"prompt":"..."}} reviewer disappears after load, and a profile that only had such workers fails in selectReviewProfile before the new drop notice can print.

The fetchOwnershipURLs helper passes the wrong error to checkpointRemoteIsInherited. When getRemoteURL(ctx, lead) fails, the error is silently discarded and fetchOwnershipURLs returns nil. This means a transient error (network timeout, invalid git state) can make the ownership check incorrectly classify a legitimate checkpoint_remote as inherited, causing the fetch to silently fall back to origin and potentially read stale checkpoints. The function should either propagate the error up through fetchURLAuthoritative or at minimum log it, matching the push side's error handling for remote URL resolution.
