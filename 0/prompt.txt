## 3. Answered, no change — why the guard is `!installed && external` and not just "remove from installed"

Because "remove only from those reported installed" would change built-in behaviour, which is what point 1 says not to do. Before this branch, `removeAgentHooks` called `UninstallHooks` on *every* hook-supporting agent unconditionally; `wasInstalled` only decided whether to print the `Removed ... hooks` line. Narrowing that to installed-only would stop cleaning up a built-in whose hook config is partial or stale in a way `AreHooksInstalled` does not recognise as installed — a real case for the built-ins, since the check compares against an embedded template.

So the guard is deliberately narrow: the new, stricter rule applies only to the new, expensive, mutating-subprocess case (external plugins, where discovery registers every `entire-agent-*` on `$PATH`, not just the one the user enabled). For built-ins the call stays unconditional because it is in-process, idempotent, and cheap.

Nothing pins that asymmetry today — every new test exercises the external side. Please add one small test: a built-in hook-supporting agent absent from the installed set still gets `UninstallHooks` called. Item 4 makes this easy to register without leaking.
