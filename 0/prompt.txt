# Repository endpoint map — Entire CLI

## How the two planes are wired

- **Control-plane core (`coreapi`)**: `coreapi.New()` dials the active-context login core; `coreapi.NewForCluster(ctx, host)` dials the core *fronting a specific cluster* (discovered via `/.well-known/entire-cluster.json`). Base path is `&lt;core-host&gt;/api/v1` (`internal/coreapi/client.go:18`, `apiBasePath = "/api/v1"`). All the `entire repo …` commands run through the `runCore*` helpers in `cmd/entire/cli/corecmd.go` (`runCore`:394, `runCoreForCluster`:405, `runCoreList`:152, `runCoreListForCluster`:159, `runCoreObject`:217, `runCoreMutation`:367, `runControlPlaneDelete`:73), which all take a `*coreapi.Client`.
- **Data-plane / entire-api cell (`api.Client`)**: two flavors — the data-API/BFF client `NewAuthenticatedAPIClient` targeting `api.BaseURL()` (`cmd/entire/cli/api_client.go:21`), and the per-cell client `auth.NewEntireAPICellClient` / `NewAuthenticatedEntireAPICellClient` (`cmd/entire/cli/api_client.go:62`) that dials a specific entire-api cell directly with a jurisdictional identity token. Cell targeting logic lives in `cell_target.go` (single repo) and `cell_fanout.go` (multi-repo).

## Endpoints called against BOTH planes (core to resolve, then cell)

These are the cases you flagged — a repo is resolved to a cell/ULID via **core catalog/mirrors first**, then the actual call hits the **cell**:

1. **`entire experts`** — core `GET /api/v1/mirrors` (via `resolveRepoCellTarget` → `resolveRepoClusterHost`, `cell_target.go:107`) + `GET /api/v1/clusters` (`cell_target.go:68`) to pick the owning cell, **then** cell `GET /api/v1/repos` + `POST /api/v1/repos/{repoId}/experts`. Best-effort: any core-resolution failure falls back to home-jurisdiction routing (`cell_target.go:53-88`).

2. **`entire recap` / `entire activity`** — core `GET /api/v1/mirrors` via `currentRepoRef` → `listMirrorsForRepo` (`entireapi_client.go:90`) to turn `origin` into the repo ULID, **then** cell `GET /api/v1/me/recap?repo={ulid}` (`recap.go:206-211`).

3. **`entire api … {repo_id}`** — core `GET /api/v1/mirrors` via `resolveCurrentRepoID` → `listMirrorsForRepo` (`api_cmd.go:198-205`, using `coreapi.New()`) to expand the `{repo_id}` placeholder, **then** the templated request against `--to core` or `--to cell` (`api_cmd.go:134-140`).

In all three, the core mirror lookup is the same `listMirrorsForRepo` helper (`repo_clone.go:180`), reused as the repo→cell resolver.</result>
