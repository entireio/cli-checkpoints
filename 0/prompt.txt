reconcileWorktreePathForResumedTurn (called at manual_commit_hooks.go:2339) rewrites state.WorktreeID before migrateShadowBranchIfNeeded runs at line 2348. migrateShadowBranchToBaseCommit looks up the existing shadow branch via checkpoint.ShadowBranchNameForCommit(state.BaseCommit, state.WorktreeID), which embeds a hash of WorktreeID in the branch name. If the relocation actually changes the worktree identity (e.g. resuming from a differently-named linked worktree, or from a linked worktree into the main worktree where WorktreeID becomes ""), the old shadow branch — created under the pre-relocation WorktreeID — will no longer be found (repo.Reference returns not-found), so the code silently falls into the "first checkpoint after HEAD changed" branch and starts a fresh shadow branch. The prior shadow branch is left orphaned and its checkpoints become unreachable via GetRewindPoints/ListCheckpoints (which also key off state.WorktreeID), permanently losing rewind history for turns made before the relocation. This case isn't covered by the new tests because the repo-rename test only exercises the main worktree, where WorktreeID is always empty before and after, masking the bug.
