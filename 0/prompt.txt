Routing a bare, flag-only `entire enable --yes` (or any interactive first run) through `runConfigureOnboarding` (via `enableUsesConfigureOnboarding` at `setup.go:971`) forces `ensureConfigureLogin`, which — when no valid token exists — calls `deps.runLogin` (`configure_onboarding.go:309`). In a CI/non-interactive context (`CanPromptInteractively()` false, e.g. `CI=true`), `runLoginAuto` falls back to the unattended device-code flow and polls `waitForApproval` for up to `maxExpiresIn` (15 minutes, see `login.go:35`) before failing, since nobody can approve the code. This breaks the previously offline-friendly `entire enable --yes` (see `reportRepoEnabled`'s comment that "enabling works offline") for any repo with a GitHub origin remote that isn't already authenticated — a very common first-run CI scenario — turning an instant local setup into a multi-minute hang followed by failure.
