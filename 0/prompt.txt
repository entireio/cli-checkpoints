1. redact: verify JSONL redaction lands, re-encode any line it misses

Hardening statement: redaction output is certified (RedactedBytes), but the certification is currently asserted, not verified. This change backs it with a per-line post-condition and a structural fallback, so the byte-preserving fast path stays byte-preserving and every other line is redacted by construction.

Where: redact/redact.go — applyJSONReplacements (:904), redactJSONLLines (:807), redactSingleJSONValue (:654).

Steps:

1. Refactor the leaf walk to two consumers. collectJSONLReplacements (:991) currently returns (original, redacted) pairs. Extract the walk so it can either collect pairs (fast path, unchanged) or return a redacted copy of the decoded tree, applying the same shouldSkipJSONLField / shouldSkipJSONLObject / credential-context rules. One walk, two outputs, so the skip rules cannot drift apart.
2. Add the post-condition. After applyJSONReplacements returns, and only for lines that had replacements: decode the spliced result and walk its string leaves. If any leaf still equals a replacement's original (honoring the pair's key scoping), the splice did not land. Comparing decoded values against the recorded originals avoids any assumption that the redactor is idempotent.
3. Fall back structurally on a miss. Re-encode the line from the redacted tree (encoder with SetEscapeHTML(false), reattach the line's surrounding whitespace). Formatting fidelity is deliberately sacrificed only for lines the splice could not rewrite. If the marshal itself fails, return an error — JSONLBytes then refuses to certify rather than shipping the line, which is the direction the RedactedBytes contract requires.
4. Apply the same treatment to redactSingleJSONValue, which shares applyJSONReplacements for whole-document content.
5. Tests. The two cases I confirmed on main become regression tests with flipped assertions: a leaf containing raw U+2028 (Go's encoder escapes it even with HTML escaping off, so the search key never matched), and a line using \/. Add: \uXXXX-escaped ASCII, non-ASCII written ensure_ascii-style, a duplicated leaf value, a keyed replacement, and a fast-path test asserting byte-identical output for a line with no encoding variance. My throwaway repro (redact/report_item3_verify_test.go in the scratchpad worktree) can seed these.

Suggested commit message: redact: verify each JSONL splice landed and re-encode lines it cannot rewrite — body: "applyJSONReplacements splices by matching the re-encoded leaf against the raw line. JSON admits more than one encoding of the same string, so a producer's encoding choice could leave a leaf outside the splice's reach with no signal. Redaction now re-checks every spliced line against the collected originals and falls back to a structural re-encode of that line; a line that cannot be rewritten fails the redaction rather than certifying."
