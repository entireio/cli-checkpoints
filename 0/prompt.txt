1. **Right layer — confirmed.** `interactive.CanPromptInteractively()` (`cmd/entire/cli/interactive/interactive.go:36`) is the correct home. Every one of the ~45 call sites I enumerated (grep across `cmd/entire/cli/**/*.go`, excluding tests) already treats "can I prompt" as one policy decision — adding a narrower `CanPromptFromGitHook()` would fork that policy and require every non-hook site to separately learn about raw-mode TUIs (any of them can also be invoked as a lazygit/gitui custom command, e.g. `entire session resume`, `entire attach`, `entire trail resume`). Classification of the cited sites:
   - **(a) blocking prompt / picker gate**: `cmd/entire/cli/strategy/manual_commit_hooks.go:504` (the actual bug site), `manual_commit_opf_prompt.go:65`, `hooks_git_cmd.go:91/114` (policy-upgrade message — arguably (b), see below), `resume_picker.go:69`, `attach.go:861`, `checkpoint_resume.go:251`, `repo_clone.go:305`, `repo_mirror_use.go:519`, `setup.go:470/1702/2281`, `investigate/cmd.go` (several), `trail_resume_cmd.go:267/355/359`, `review/cmd.go:286`, `login.go:101`.

Concretely: under lazygit, a checkpoint-policy-unsupported or policy-diverged warning that used to print to stderr (visible in lazygit's captured-output panel, since child stdout/stderr is piped, not painted directly to the raw terminal) will now silently downgrade to `logging.Warn` only — the user loses visibility into "your checkpoint work is being skipped" specifically in the client where they're most likely to be committing repeatedly. This is a real behavior change riding along on a fix aimed at a different mechanism (`/dev/tty` blocking read), and the existing unconditional `warnIfAttributionDiverged` proves the codebase itself doesn't believe plain-stderr writes need this gate.
   - **Deeper/better placement**: gate categories (a) and (b) on two different predicates — `CanPromptInteractively()` (raw-mode-aware) for anything that opens `/dev/tty` or runs a huh/bubbletea program, and a plain `IsTerminalWriter(os.Stderr)`-style check (no raw-mode logic) for one-shot warnings that only write, never read. `checkpoint_policy.go` and `hooks_git_cmd.go`'s warning branches should move to the latter.

**1. Ready-made cross-platform termios reader already in the dependency graph — the new per-OS ioctl files duplicate it**

- File: `cmd/entire/cli/interactive/rawmode_darwin.go:14-22`, `cmd/entire/cli/interactive/rawmode_linux.go:14-22`
- `github.com/charmbracelet/x/termios` v0.1.1 is **already** in the build graph (`go mod why github.com/charmbracelet/x/termios` → required by `charm.land/bubbletea/v2` → `github.com/charmbracelet/ultraviolet` → `github.com/charmbracelet/x/termios`, and currently listed as `// indirect` in go.mod). It exports:
  ```go
  // termios.go
  func GetTermios(fd int) (*unix.Termios, error) {
      return unix.IoctlGetTermios(fd, ioctlGets)
  }
  ```
  This is a non-mutating read (unlike `x/term`'s `MakeRaw`/`SetState`), it returns the real `*unix.Termios` (exported `Lflag` field, so `ICANON` is directly checkable), and it already resolves the darwin-vs-linux ioctl-number split internally (`termios_bsd.go`: `ioctlGets = unix.TIOCGETA`; `termios_linux.go`: `ioctlGets = unix.TCGETS`).
- Cost of the current approach: two near-identical 9-line files (`rawmode_darwin.go`, `rawmode_linux.go`) reimplement exactly what `termios.GetTermios` already does, plus they hand-pick `TIOCGETA`/`TCGETS` per OS — logic that already exists and is already pulled in.
- Fix: replace both platform files with one call in a single non-Windows file:
  ```go
  t, err := termios.GetTermios(int(f.Fd()))
  if err != nil { return false }
  return t.Lflag&amp;unix.ICANON == 0
  ```
  and promote `github.com/charmbracelet/x/termios` from `// indirect` to a direct require (it's a leaf package — only depends on `golang.org/x/sys/unix` and stdlib `syscall` — so no cycle risk importing it from `cmd/entire/cli/interactive`).

**2. `golang.org/x/term` (existing direct dep) has no usable raw-mode probe — confirmed, not a finding against the current code**

- Checked `$(go env GOMODCACHE)/golang.org/x/term@v0.45.0/{term.go,term_unix.go}`. Public surface: `IsTerminal`, `MakeRaw`, `GetState`, `Restore`, `GetSize`, `ReadPassword`. `MakeRaw`/`Restore` mutate. `GetState` is non-mutating but returns `*term.State{ state{ termios unix.Termios } }` — `state` and its `termios` field are **unexported**, so a caller cannot read `Lflag`/`ICANON` off it. No exported API in `x/term` answers "is this fd currently in canonical/raw mode" without mutating. So `x/term` is correctly *not* reused here — but see finding 1, `charmbracelet/x/termios` (already a transitive dep) does expose exactly that, unlike `x/term`.
