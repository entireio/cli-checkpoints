`configureGitHubAdmin` (`configure_onboarding.go:312-322`) folds every failure mode — `gh` not installed, `gh` not authenticated, network error, rate limit — into a single generic error. Here, `adminErr != nil` is treated identically to `!admin`, so a repo admin who simply lacks a working `gh` CLI locally is told "An admin needs to install the GitHub app first... send them this link" and the flow hard-exits via `NewSilentError`, even though they could complete the install themselves. The codebase already has the correct pattern for this exact dependency elsewhere (`setup_github.go`'s `ghAvailable`/`ghAuthenticated` checks with distinct, actionable messages) — this path should distinguish "check failed" from "check returned false" instead of blocking with misleading guidance.
