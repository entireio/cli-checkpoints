## Findings, most severe first

### 1. CRITICAL — "None of them ever inspect image content" is false, and the codebase says so in two places

**Doc (line 41, and restated at 43, 50, 380, 531):** *"Every layer described above — all nine passes … operates only on transcript text. None of them ever inspect image content."* / *"it is stored **completely unredacted, byte-for-byte identical to what you pasted**"* / *"pasted images are never scanned or redacted by any layer"*

The image skip is **not** an image exemption. It is one narrow predicate, `redact/redact.go:1053-1056`:

```go
func shouldSkipJSONLObject(obj map[string]any) bool {
	t, ok := obj["type"].(string)
	return ok &amp;&amp; (strings.HasPrefix(t, "image") || t == "base64")
}
```

It fires on the *enclosing object's* `type`. Claude Code's shape (`{"type":"image","source":{"type":"base64",…}}`) matches. **Codex's does not.** Codex serializes every inline image as a data-URI inside a string leaf — `{"type":"input_image","image_url":"data:image/png;base64,…"}` — per `cmd/entire/cli/transcript/imageextract/imageextract.go:271-273, 311-336` and the fixtures in `codex_test.go:17,108-110`. `"input_image"` has no `image` prefix, and `image_url` is not in `shouldSkipJSONLField` (`redact.go:1025-1050`), so the base64 reaches the redactor and layer 1 (entropy, `redact.go:187-210`, `secretPattern = [A-Za-z0-9+_=-]{10,}`, threshold 4.5) shreds it.

Verified empirically against the production redactor (`redact.JSONLBytes`, which is what `redactSessionJSONLBytes` at `manual_commit_condensation.go:143-145` and `RedactBlobBytes` at `persistent.go:2581-2588` actually call), using a 64×64 noise PNG:

| stored shape | byte-identical | base64 intact | `REDACTED` count |
|---|---|---|---|
| Claude `type:"image"` | **yes** | yes | 0 |
| Codex `input_image` + data-URI | **no** | **no** | **170** (16,568 B → 3,264 B) |
| `type:"image_url"` object | yes | yes | 0 |
| Codex data-URI in `function_call_output` | **no** | **no** | 170 |
| bare data-URI in assistant text | **no** | **no** | 170 |

The codebase already states this outright, twice:

- `cmd/entire/cli/strategy/manual_commit_condensation.go:208-209` — *"Externalize before redaction, because base64 is high-entropy and **redaction would otherwise flag and destroy it**."* That ordering is load-bearing precisely *because* inline images are inspected.
- `cmd/entire/cli/strategy/manual_commit_hooks.go:3197-3198` — *"clearing the previously-stored assets would permanently lose them (**the re-inlined base64 is destroyed by redaction below**)."*

**What a reader gets wrong:** a Codex user reads "byte-for-byte identical to what you pasted" and "never scanned by *any* layer", concludes their pasted screenshot is sitting intact in checkpoint history, and acts on that — either fearing an exposure that isn't there, or trusting the doc's *general* rule when auditing a Claude Code repo where it *is* there. The true rule is agent- and shape-dependent: unredacted only where `shouldSkipJSONLObject` happens to match. Secondary case with the same root cause: `RedactBlobBytes` (`persistent.go:2581-2597`) falls back to whole-content byte redaction when the JSONL parse fails, and that fallback destroys even the Claude shape — the exemption depends on a successful JSON parse, not on the content being an image.

The narrow claims *are* sound and worth keeping: the **externalized** form genuinely never gets inspected (`writeAssets`, `persistent.go:1875-1912`, blobs the raw bytes with no redaction call — see finding 4), and OPF genuinely never sees images (finding 5). The universal negative over all nine passes is what fails.

### 2. HIGH — "By default, the image stays inline in the stored transcript as base64" is wrong for most supported agents

**Doc (line 45).** Only two agents have an image codec — `imageextract.go:104-107`: `codecs = {AgentTypeClaudeCode, AgentTypeCodex}`. And only Cursor implements the sidecar provider (`cmd/entire/cli/agent/cursor/images.go:59`; it is the only `SidecarImages` implementation in the tree).

- **Cursor:** images live in Cursor's own SQLite store and, per `manual_commit_condensation.go:461-463`, *"never appear in full.jsonl."* Capture is gated on the same flag (`:469-471`), so **by default a pasted Cursor screenshot is not stored in the repository at all.** The doc tells that user their image is inline in the transcript. It is not — it is outside the repo entirely.
- **Codex:** destroyed, not inline (finding 1).
- **Gemini / OpenCode / Copilot CLI / Pi / Droid:** no codec, no sidecar provider — outcome depends on each agent's own transcript shape, and the doc asserts one answer for all of them.

The paired claim at line 46 — *"the image is lifted out … and written as a raw binary blob under the checkpoint's `assets/` folder **instead**"* — is likewise only true for Claude Code, Codex, and Cursor. For every other agent, enabling `externalize_images` changes nothing (`imageextract.go:110`: `CodecFor` returns nil → `extractSessionImages` passes through unchanged, `manual_commit_condensation.go:152-155`). The section's framing — "Where it is stored depends on one setting … the exposure is the same either way" — presents a two-outcome matrix where the real matrix is agent × setting, and one of its cells ("not stored anywhere") is the *safe* one the doc denies exists.

### 3. MEDIUM — the pasted image lands on the shadow branch at turn end, which the section's storage account omits and its timing claim contradicts

**Doc (line 48):** *"Either way the bytes become part of checkpoint content on `entire/checkpoints/v1` (or the equivalent per-checkpoint ref on the `git-refs` backend). Like all checkpoint data, that is written locally at commit time and pushed separately."*

There is a third destination and an earlier time. The Stop/shadow write walks `.entire/metadata/&lt;session&gt;/` through `createRedactedBlobFromFile` (`ephemeral.go:1018,1058`) and **never externalizes** — the only three `IsImageExternalizationEnabled` call sites are `manual_commit_hooks.go:3200` (finalize) and `manual_commit_condensation.go:182,470` (condensation). CLAUDE.md states the same: *"the Stop/shadow write … **no externalization**, so inline images in a shadow transcript are subject to redaction and assets exist only under committed checkpoints."* So a Claude Code screenshot is committed as a raw blob into local git objects **at turn end, before any commit, and regardless of the setting**.

The exposure conclusion survives (shadow branches aren't pushed, per the pre-existing paragraph at line 20), but *"written locally at commit time"* is wrong, and the sentence immediately following — *"That gap is your window to inspect it"* — points at `entire checkpoint list` / `git log entire/checkpoints/v1` (line 380-390), neither of which shows the shadow-branch copy that already exists. A reader auditing "did this image reach git?" before their first commit would check the two places named, find nothing, and be wrong.

Minor, same sentence: with the setting **off**, the base64 is stored **twice** per checkpoint — `full.jsonl` and the compact `transcript.jsonl`, which passes image blocks through verbatim (`transcript/compact/compact.go:321-322`, *"Image blocks passed through verbatim"*). ### 4. LOW–MEDIUM — `ENTIRE_EXTERNALIZE_IMAGES=1` is not an "equivalent override"

**Doc (line 46):** *"the `ENTIRE_EXTERNALIZE_IMAGES=1` environment variable is an equivalent override"*.

Two gaps in `settings.go:1772-1780`:

```go
if v := os.Getenv("ENTIRE_EXTERNALIZE_IMAGES"); v == "1" || v == "true" {
```

`"true"` is also accepted (the doc names only `1` — harmless omission). The real problem is "equivalent": the env var is **not inherited by hook processes**, so it can be on at condensation and off at finalize. That is a known, guarded case, named in the code and in a dedicated test: `manual_commit_hooks.go:3194` (*"an `ENTIRE_EXTERNALIZE_IMAGES` env override not inherited by the hook process"*) and `integration_test/image_externalize_test.go:130-138` (`TestImageExternalization_FinalizeWithFlagOffPreservesAssets`). A reader who exports the env var and believes it equals the setting will get inconsistent behaviour across the session's write paths; the setting file is the only reliable switch.

Also strictly-unconditional-as-written: externalization skips base64 shorter than 64 chars (`minExternalizedBase64Len`, `imageextract.go:90-95`), images above `agent.MaxChunkSize` (`maxExternalizedImageBytes`, `:97-102`), and anything whose base64 doesn't re-encode byte-exactly (`:160-167`) — those stay inline even with the flag on.
