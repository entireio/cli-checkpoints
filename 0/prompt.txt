One thing left, which I should have raised alongside the last comment rather than after it. The OPF sites are gated on `redirectedToSyncRemote()` while the empty-remote defer uses `targetsEntireRemote()`:

```
173:  if ps.redirectedToSyncRemote() {   // OPF decision failure
206:  if ps.redirectedToSyncRemote() {   // boundFallback
212:  if ps.redirectedToSyncRemote() {   // skipRedirectedCheckpointPush
409:  if ps.targetsEntireRemote() {      // empty-remote defer
```

`redirectedToSyncRemote()` is `syncRemote != ""`, which is only set when the push names a *different* remote. So a direct `git push entire` on an OPF + git-branch repo with more than `bootstrapDefaultLimit` v1 commits gets neither the fallback bound nor the withhold, and takes the original abort path — the case the bounded rewrite exists for. `recordDisplacedCheckpointRemote` runs on that push too, so the recorded name is right there; only the predicate is keeping it out. Widening all three to `targetsEntireRemote()` looks like the whole fix.
