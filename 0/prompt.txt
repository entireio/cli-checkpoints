## Recommended shape: unconditional rename-then-replace, no probe
Rather than probe-then-decide, always do the updater pattern when the target exists:

4. **Rollback:** if the copy in step 2 fails, `Move-Item` the `.old` back before rethrowing, so the user is never left with no binary.
5. **Sweep on the next run:** before writing, try to delete any stale `<binary>.old` left by a previous install (silently), so they don't accumulate.
6. If the `Move-Item` in step 1 itself fails (a handle opened without `FILE_SHARE_DELETE` — an AV scanner, an editor), catch and throw a message naming the path and the remedy ("close entire and any tool holding <path>, then rerun"), instead of the raw IOException.

The only thing the probe bought was a nicer message, and step 6 gives that where it's actually needed. If you disagree, argue it with a case the unconditional path handles worse.

Ordering constraint to preserve: checksum verification and extraction happen **before** any move. The swap is the last thing that touches the install dir, and it operates on files already verified in the temp dir.
