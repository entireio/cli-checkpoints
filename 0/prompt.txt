# Final Branch Review: `install-tracking-posthog`

## Verdict: NOT READY — two Important fixes first (both small, neither breaks the build)

The wiring is genuinely correct end-to-end and the code is clean. Method strings are consistent across all three channels, there's no import cycle, opt-out gating is faithful, and it mirrors the existing `cli_command_executed` / `cli_plugin_executed` patterns well. But two things will ship *misleading* behavior for a feature whose entire value is accurate, pre-consent install counting. Both are one-liners.

## What I verified as correct (not just present)
- **End-to-end chain connects.** `TrackInstallDetached(method, version)` → `BuildInstallEventPayload` → `spawnDetachedAnalytics` → hidden `__send_analytics` → `SendEvent` → `posthog.Capture`. Event name `cli_installed`, `distinct_id` = `machineid.ProtectedID("entire-cli")` (hashed machine id, not identity), 5 designed properties all present with correct types.
- **Method strings consistent:** curl → `"install.sh"` (setup.go:2080); scoop → `--method scoop` (.goreleaser.yaml:124); brew → `["__track-install","--method","brew"]` (both casks). All match the design table and the docs.
- **No import cycle.** `versioncheck` does not import `telemetry`; the new `telemetry → versioncheck` edge (detached.go:14) is one-directional. `root.go` already imported `versioninfo`. `markRequired` exists (corecmd.go:623).
- **No double-fire / no network during install.** `PersistentPostRun` walks the parent chain and returns early for Hidden commands (root.go:66-71), so `__track-install` and `curl-bash-post-install` do *not* also emit `cli_command_executed` or run the version-check network call. Good.
- **Detached, non-blocking.** The grandchild flushes after the installer's post-install step returns, as designed.

## Important (should fix before merge)

- **`scripts/install.sh:289-337` — first-time curl installs never fire the ping.** The ping is only reached at line 337 (`"$install_path" curl-bash-post-install`), which lives *after* the `elif [[ -z "$path_binary" ]]` branch whose own comment reads "First-time install: ~/.local/bin likely isn't on their PATH yet." That branch always `exit 0`s at line 328 or 332 before reaching 337. Net effect: `cli_installed` via install.sh fires *only when `entire` already resolves on PATH to the new binary* — i.e. re-installs/upgrades — and systematically misses brand-new installs, the exact population the event exists to count. Line 337 already uses the full `"$install_path"`, so PATH isn't required; the same call could run in the early-exit branch. This under-counts the curl channel silently (brew/scoop unaffected).

- **`detached.go:194-199` vs `docs/security-and-privacy.md:502` — undisclosed `git_version` on the install event.** `SendEvent` appends `git_version` to *every* payload it processes, including `cli_installed`. So the event actually delivered to PostHog carries 6 properties, but the design schema and the new "Install event" doc subsection enumerate a closed set of 5 (`method`/`channel`/`cli_version`/`os`/`arch`) with no `git_version`. It's non-PII, but for an event that fires *before consent* the per-event disclosure should be exact — either add `git_version` to the doc's install-event list or skip it for `cli_installed` in `SendEvent`.

## Minor
- **`scripts/install.sh:336`** — the notice prints immediately before the ping fires, so "Set `ENTIRE_TELEMETRY_OPTOUT=1` to disable" gives no real opt-out window at that point. The docs correctly say "before installing"; the install.sh line should say the same (e.g. "…set it before installing to disable") to avoid implying it can still be set in time.
- **`root.go:148`** — `--method` help text reads `"(brew|scoop)"` but the curl path passes `install.sh`; enumerate all three or make it generic.
- **`root.go:141` vs `:143`** — cosmetic naming drift: `__send_analytics` (underscore) vs `__track-install` (hyphen). Not worth churning existing code, just noting.

## Praise
- Reuses `EventPayload` / `spawnDetachedAnalytics` / `machineid` rather than adding a parallel PostHog path — exactly the "peer event" shape the design called for.
- Correctly gates *only* on `ENTIRE_TELEMETRY_OPTOUT` (not `settings.Telemetry`), matching the pre-consent decision, and documents why.
- `BuildInstallEventPayload` returning `nil` on machine-id failure, plus the opt-out early return in `TrackInstallDetached`, are clean best-effort guards. Tests cover event name, derived channel, and the opt-out no-op seam.
