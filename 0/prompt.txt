The cli handles push to forks differently than it does normal repositories, as in fork users generally don't have permission to push into the upstream repository. For public repositories with a private remote checkpoint target setup, the existing handling is a bit problematic, as it would silently push the checkpoints to the public repository from the fork owner potentially causing privacy concerns. Let's brainstorm the different options we have to improve the UX for fork users, and initially resolving that specific problem.
