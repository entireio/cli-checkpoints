In the non-interactive branch of `promptConfigureUpstreamAndAgents`, `selectedAgentNames` is built only from agents already installed or auto-detected by `configureAgentPreselection` — if neither exists (e.g. `entire enable`/`entire configure --yes` run in an environment with no detectable agent CLI, a plausible case for automated/agent-driven setup), `selectedAgentNames` ends up empty and there is no validation requiring at least one agent, unlike the interactive `configureAgentField`'s `Validate` requiring ≥1 (`newConfigureAgentControl(agentOptions, &selectedAgentNames, true)` at line 770). With zero agents selected and zero previously installed, `configureSelectionChanges` reports `agentsChanged=false`, so `runEnableInteractive` (and hook/settings installation) is skipped entirely in `runConfigureOnboardingFlow`, yet the flow still prints `✓ Configuration complete` / `You're set. Start a session with any selected agent`. This silently completes setup with no agent hooks installed at all, a regression from the old `detectOrSelectAgent` non-interactive path which always fell back to `agent.Default()` or errored with `no agents selected`.
