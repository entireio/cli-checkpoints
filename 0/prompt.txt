`TrailsEnabled` now defaults to the entire-api `pageSize=1` query unless the client was explicitly tagged with `WithTrailBackend("legacy")`. But `setup.go`'s enable-report probe and `agent_help_cmd.go`'s `refreshAgentHelpTrailsEnabledCacheIfStaleForScope` both build their client via plain `NewAuthenticatedAPIClient` (untagged) and still hit the legacy BFF exclusively — they never call `newTrailAPIClient`/`WithTrailBackend`. Before this change these call sites always sent `limit=1`; now they silently send `pageSize=1` to the legacy endpoint instead, which is a behavior change these callers weren't updated for.
