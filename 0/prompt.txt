`configureBranchHasNoUnpushedCommits` gates `branchPushSafe`/`requiresPush` using `@{u}`, i.e. the branch's tracking remote (`origin`). But `configureUseMirror` (via `applyMirrorRemotePlan`) repoints `origin`'s URL to the read-only Entire mirror without ever updating `branch.<name>.remote`/`.merge` for the checked-out branch. For a protected branch, the push flow only sets `-u` on the ephemeral review branch, never on the real branch, so `origin` stays its tracking remote permanently. Once ordinary commits land on that branch afterward (PR merges, etc.) with nothing re-fetching the now-irrelevant `origin` ref, `rev-list --count @{u}..HEAD` will report a nonzero count forever, making `requiresPush()` false. That silently removes **both** the direct-push and "push to a new branch, review before it lands" options from `configureSaveOptions`, forcing every subsequent `entire configure` run on an already-onboarded protected-branch repo into local-save-only — defeating the documented review-branch feature.

---

Wouldn't it make sense to keep part of the save/push step for entire agent too?
