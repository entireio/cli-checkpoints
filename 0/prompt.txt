`runConfigureAgentManagement` calls `configureRetargetCurrentBranch` unconditionally before the interactive `promptConfigureAgentsAndSave` prompt even runs. This mutates the current branch's `branch.<name>.remote` git config as a side effect of merely opening `entire agent` (when the repo is already set up) — even if the user immediately cancels or makes no agent changes. Contrast with `runConfigureOnboardingFlow`, where the equivalent mutation (via `configureUseMirror`) only runs after the save choice is confirmed and not `configureSaveCancel`/empty. This breaks the expectation that cancelling the agent menu leaves repo state untouched.
