brainstorm:
We'd like to extend the scope of the 'trail' domain object.

- the trail should 'contain' or be able to reference multiple 'change requests'
- a 'change request' could be the current entire trail model with runners (and associated results, comments, etc) as well as external things like PRs or whatever exists on other forges (so a set/list)
- it may exist at repo or project (or perhaps even org!) level
- we want to be able to mark relations to other trails, perhaps even with parent-child relationships (similar to linear issues?)

and finally, but probably separately, we need to have an audit history on the trail body/intent so we can see how the intent has changed over time.

the current trail implementation likely keeps the existing fields (inc. body scoped to that specific change)
