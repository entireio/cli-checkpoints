In the non-interactive (`--yes`) path, `promptConfigureUpstreamAndAgents` returns `defaultConfigureSaveChoice(hasChanges(), ...)` directly (`configure_onboarding.go:840`), which yields `configureSaveCancel` whenever nothing changed. The interactive path instead normalizes this same no-op case to `saveChoice = ""` (line 862) so the caller prints "No configuration changes." For `--yes`, an idempotent rerun with nothing to change instead prints "Configuration cancelled." (line 192), which misleadingly reads as if the run was aborted rather than a successful no-op. Consider applying the same `hasChanges()` normalization in the `nonInteractive` branch.
