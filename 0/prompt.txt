- `cmd/entire/cli/agent/testing.go:31` — low/medium. `restore` assigns the snapshot map itself (`registry = snapshot`) instead of copying back into a fresh map, so restore is not repeatable. After the first call the package-global `registry` *is* `snapshot`, so any later `Register` mutates the snapshot and a second `restore()` is a no-op. Concrete scenario, and it is the exact shape of the new test `TestSnapshotForTesting_RestoresRegistry` (which registers `restore` with `t.Cleanup` *and* calls it directly): `restore := SnapshotForTesting(); t.Cleanup(restore); … restore(); agent.Register("mock", …)` — the cleanup then leaves `mock` in the registry, and since these mocks are backed by `t.TempDir` binaries, a later test's `GetAgentsWithHooksInstalled` execs a deleted file. The doc comment claims restore returns the registry "to exactly that state", and only calls out concurrent *writers* as the exception. Fix: `registry = maps.Clone(snapshot)` inside the returned closure.

- `cmd/entire/cli/agent/registry.go:97` — low. `ListAvailable` resolves each name with `Get`, whose miss branch calls `StringList()` → `ListAvailable()` → `Get(...)`, i.e. mutual recursion, purely to format an error string that `ListAvailable` immediately discards. When a name does vanish between `List()` and `Get()` — the case the doc comment explicitly anticipates ("a concurrent restore of a testing snapshot") — each vanished name pays a full re-resolution of the whole registry, and nothing bounds the recursion if entries keep disappearing.
