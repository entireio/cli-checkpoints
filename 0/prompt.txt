`configureOnboardingEnableOptions` unconditionally sets `SuppressAdditionalSetup: true`, so the new `entire configure`/first-run `entire enable` onboarding path (which is now the default interactive entry point) never calls `maybePromptVercelDeploymentDisable` — see the guard at `cmd/entire/cli/setup.go:1394`. Repos hosted on Vercel that onboard through this new flow will no longer be asked to disable auto-deploy for `.entire/` commits, and there is no replacement prompt anywhere in `configure_onboarding.go`, so the configuration commit this flow itself creates and pushes can silently trigger unwanted redeployments.
