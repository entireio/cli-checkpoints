THE FINDING (HIGH) — a server-supplied ref name can inject into the git remote-helper protocol

Threat model: a malicious or compromised git server. This CLI ships a git remote helper (git-remote-entire) that speaks git's remote-helper protocol on stdout. Ref names come from the server's advertisement and are echoed into that protocol stream.

internal/remotehelper/githelper/list.go:60:

    line := strings.TrimRight(string(content), "\n")

Only TRAILING newlines are trimmed. The result is then emitted (around :112-119) as:

    fmt.Fprintf(stdout, "%s %s\n", value, name)

pkt-lines are length-delimited, so a hostile server can embed \n INSIDE a ref name. It survives TrimRight and goes straight into the protocol stream.

A PoC against a fake transport confirmed this. A ref named:

    refs/heads/ok\n<sha> refs/heads/injected\n\nok refs/heads/main\n

produced an injected blank line that TERMINATES THE REF LIST EARLY — truncating the real refs and the trailing "@<ref> HEAD" symref line — and left residue sitting in the stream exactly where canonical git reads the NEXT command's response. "ok <ref>" / "error <ref>" is precisely the shape of a push response, so a malicious server can plant a FORGED PUSH RESULT: git reports a push succeeded that did not.
