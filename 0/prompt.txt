Ok, there are two more proposed solutions here - is there overlap with the existing findings for either of these alternative options?
- Never give the child a pipe. Set cmd.Stdout to an *os.File (temp file, or os.DevNull for stderr you don't need). exec then dups the fd directly — no pipe, no copy goroutine, and Wait returns the moment the direct child dies no matter what grandchildren do. Read the file afterwards. Cross-platform, no signals, no delay budget. Cost: temp-file plumbing, and you lose incremental/streaming reads. This is the strongest structural fix for the capture-into-buffer callers specifically.
- Bound the caller instead of the process. Start(), Wait() in a goroutine, select on that vs ctx.Done(). The command returns on the deadline with certainty; reaping is left to a background goroutine. Guarantees the user-visible deadline even if both A and B are defeated, at the cost of a leaked goroutine/zombie. Complements rather than replaces B.
