### 1. `internal/entireclient/clusterdiscovery/resolve.go:295-302` — the `errors.New(Sprintf + Sprintf + literal)` construction is unnecessary; a variable does the same job

The two error branches interleave `fmt.Sprintf` calls with `+` and a bare literal, so the rendered message can't be read in one place. The comment (lines 289-292) says this shape exists to keep revive's `error-strings` rule from forcing the message onto one lowercase line.

I verified with `golangci-lint` against this repo's config what actually fires:

Simpler form, one format string per branch:

### 3. `resolve.go:261-276` — `eligibleContexts` is over-built for its new report-only role, and diverges from `contextEligible`

It iterates `coreURLs × contexts` via `f.ContextsForIssuer` and needs a `seen` map only because the outer loop can visit the same context twice (duplicated / trailing-slash-variant core URLs). Flipping the loop makes duplicates structurally impossible:

```go
func eligibleContexts(f *contexts.File, coreURLs []string) []*contexts.Context {
	var out []*contexts.Context
	for _, c := range f.Contexts {
		if contextEligible(c, coreURLs) {
			out = append(out, c)
		}
	}
	return out
}
```

Six lines, no map, no nested loop, and — the real win — **one** eligibility predicate instead of two.
