```go
func getAgentHookState(ctx context.Context) agentHookState {
	var state agentHookState
	for _, name := range agent.List() {
		ag, err := agent.Get(name)
		if err != nil { continue }
		hs, ok := agent.AsHookSupport(ag)
		if !ok { continue }
		installed, err := hs.AreHooksInstalled(ctx)
		switch {
		case installed:
			state.installed = append(state.installed, name)
		case err == nil:
			// Cleanly reported no hooks.
		case ctx.Err() != nil:
			logging.Debug(ctx, "hooks-installed check abandoned: context ended", "agent", string(name))
		default:
			state.unchecked = append(state.unchecked, uncheckedAgent{
				name: name, err: err, external: external.IsExternal(ag),
			})
		}
	}
	return state
}
```

Note `case installed:` comes first — an agent that says "installed" *and* returns an error is treated as installed.

## 5. Test conventions in setup_test.go

- **Not table-driven for the uninstall paths.** One test per behaviour, each with a doc comment stating the invariant it pins ("pins that…", "must not…"). Tables appear only for pure functions: `TestEnableUsesSetupFlow` (:2394), `TestCleanRemoteURLForReport` (:4558), `TestShellCompletionTarget` (:2125) — those use `for _, tt := range …` + `t.Run` + nested `t.Parallel()`.
- **`t.Parallel()` is the exception, and its absence is always annotated.** Every non-parallel test carries a one-line reason as the first statement comment, e.g. `// Cannot use t.Parallel: mutates $PATH, cwd, and the agent registry.` Only pure-function tests call `t.Parallel()` (:1744, :2302, :2325, :2395, :4169, :4181, :4455, :4559, :4712).
- **Temp repo via `setupTestRepo`/`setupTestDir`**, relying on `t.TempDir()` + `t.Chdir()` + `t.Setenv()` for automatic cleanup; global agent registry restored with `t.Cleanup(agent.SnapshotRegistryForTesting())`; path caches explicitly cleared.
- **Output asserted as strings, not structs.** Tests pass `var stdout, stderr bytes.Buffer` into `runUninstall(ctx, &amp;stdout, &amp;stderr, true)` and use `strings.Contains` on phrase fragments ("did not complete", "has been removed from this repository", "could not check whether", "may or may not remain"). Stream discipline is part of the contract: warnings must be on stderr, verdicts on stdout.
- **Error type is asserted, not just non-nil**: `var silent *SilentError; errors.As(err, &amp;silent)`.
- Failure messages include the captured output (`, stdout:\n%s`) so a failure is diagnosable without a rerun; `t.Fatalf` for preconditions, `t.Errorf` for independent assertions.
- Externally observable side effects are asserted through an exec log file (`ENTIRE_TEST_EXEC_LOG`) with exact counts, e.g. `strings.Count(string(data), "are-hooks-installed") != 1` at setup_test.go:1313.</result>

# B) Production behaviour that changes

Which agents actually widen: **claudecode** (`Stop` → 6 hook types + `permissions.deny`), **factoryaidroid** (`Stop` → 7 types + deny), **codex** (AND of 4 core → OR of 7 events). **cursor** (`cursor/hooks.go:303-311`), **geminicli** (`geminicli/hooks.go:435-441`) and **copilotcli** (`copilotcli/hooks.go:262-269`) already OR over exactly the set their uninstall touches, so for them only the *code path* changes, not the answer — with the two exceptions in C1 and C4.

**B1. `getAgentHookState` — `cmd/entire/cli/config.go:141-172`**
More agents land in `state.installed`. Also: the `default:` branch at `:161-169` (→ `unchecked`) fires on a **different** set of malformed files now. Today the detect path unmarshals the whole file into a typed struct (`loadClaudeSettings` → `ClaudeSettings`, `CursorHooksFile`, `GeminiSettings`, `FactorySettings`, `CopilotHooksFile`), so a garbage value in *any* field errors. The removal path is raw-map and tolerant: `claudecode/hooks.go:341-346` and `factoryaidroid/hooks.go:335-340` explicitly swallow a `permissions` parse failure (`rawPermissions = nil`). Consequence: a repo with `"permissions": "oops"` and a live deny rule moves from **"could not check → uninstall exits non-zero and warns"** to **"cleanly reported, nothing to remove"** — the deny rule silently survives an uninstall that reports success. That is the exact failure mode this branch was written to prevent. The pure function must return an error (not swallow) when it cannot parse a container it is supposed to strip.

**B2. `GetAgentsWithHooksInstalled` / `InstalledAgentDisplayNames` — `config.go:180-187`**
Straight pass-through; every consumer below inherits the widening.

**B3. `entire status` — `status.go:193` (text), `status.go:808` (JSON)**
A user sees `Agents · Codex` (or Claude Code, or Droid) listed where a partial/leftover config previously showed nothing. Concretely: someone who ran `entire enable` on an old release that only wrote Codex `Stop`, or someone whose `.claude/settings.json` has only the `Read(./.entire/metadata/**)` deny rule left behind by a half-finished uninstall, now sees the agent listed as enabled. Defensible — it is what "there is something of ours here" means — but it is a visible change and the deny-rule-only case is the one that reads as a lie.

**B4. `entire agent list` — `agent_group.go:69-88`**
Same widening; the `✓` marker appears against more agents, and the `"No agents installed"` hint at `:84` stops firing in leftover-artifact repos.

**B5. `OutdatedHookAgents` / `OutdatedHookAgentDisplayNames` — `config.go:201-219`; consumed by `status.go:812` and `doctor.go:601-624` (`checkHookDrift`)**
Scoped to `GetAgentsWithHooksInstalled`, so the *candidate* set grows. Only `claudecode` (`claudecode/hooks.go:470`), `pi` (`pi/hooks.go:157`) and `opencode` (`opencode/hooks.go:136`) implement `HookFreshness`, so codex/factory/cursor/gemini/copilot widening has no drift effect. **B6. `entire doctor` — `doctor.go:601` `checkHookDrift`, `doctor.go:642` `checkCodexHookTrust`**

**B7. MIS-BEHAVIOUR: `checkHookDrift` goes silent on exactly the configs the widening newly reports as installed.**
`claudecode.CheckHookConfig` (`claudecode/hooks.go:476-490`) returns `HooksAbsent` when `!hasEntireHook(settings.Hooks.Stop)`. So a `.claude/settings.json` carrying only `PostToolUse` hooks, or only the deny rule, now:

- `entire doctor` → prints **neither** `✓ Claude Code hook config: OK` **nor** `Claude Code hooks: OUT OF DATE`, because `checkHookDrift` treats `HooksAbsent` as "nothing to report" (`doctor.go:611-613`)
- `status --json` → agent listed, `hooks_outdated` empty

i.e. the user is told the agent is enabled and told nothing is wrong, while its `Stop` hook — the one that drives checkpointing — is missing. **Fix required in this change:** `claudecode.CheckHookConfig` must return `HooksOutdated` (not `HooksAbsent`) when detection says installed but the current spec is not met. The error path at `:1597-1602` (fail rather than uninstall blind) is unchanged.

`installedNames` widens, so deselecting an agent with a partial config now actually removes it. Intended fix.

`for _, name := range selectedAgentNames { if _, wasInstalled := installedSet[name]; wasInstalled { if opts.ForceHooks { reinstall } ; continue } }`. The `continue` at `:580` means a *selected* agent that the sweep reports installed gets **no** `InstallHooks` call without `--force`. Today a codex config with only `Stop` reports **not** installed → codex lands in `addedAgents` → `setupAgentHooks` runs → `InstallHooks` syncs in the missing 6 events. # C) Hazards in the mechanism

## C1. geminicli `stripNonArrayHookFields` — the real one
`geminicli/hooks.go:238-249`, called from uninstall at `:338` (return value **discarded**) and from install at `:92` as `cleanupDone`, where it is used to force a write.

It deletes any non-array value under `hooks`, i.e. the legacy `hooks.enabled: true` that old Entire versions wrote. Two facts make this the decision point:
- Gemini CLI 0.33+ **rejects** a `hooks` object with a non-array property (per the comment at `hooks.go:89-91`). So this is not cosmetic normalisation — a config left with `hooks.enabled` is a config Gemini refuses to load.
- `hooks.enabled` is unambiguously an Entire-written artifact. Nobody else put it there.

**Does conditional-on-`changed` lose something?** Yes, in exactly one case: a config with `hooks.enabled: true` and no Entire hook entries (a repo already half-cleaned). Today `UninstallHooks` strips it and writes; under a naive `changed` it would not.
**Should it count as `changed`?** Yes — and the plumbing already exists: `stripNonArrayHookFields` returns a bool, install already treats it as write-forcing, and uninstall already discards it at `:338`. OR it into `changed`. Cost, which you should accept deliberately: `AreHooksInstalled` then returns **true** for a config whose only trace is `hooks.enabled: true`, so `entire status` lists Gemini for such a repo. That is consistent with the new definition ("removal would change this config") and it is arguably right — the file is broken *by us* and we can fix it. The alternative (don't count it) leaves a config Gemini rejects on disk after a "successful" uninstall, which is worse.
**Test consequence:** `geminicli/hooks_test.go:676` keeps passing either way (its fixture has an Entire hook too). Add the no-hook-only-`enabled` case to pin the decision.

## C2. claudecode / factoryaidroid empty-container pruning
`claudecode/hooks.go:363-393` — deletes `permissions.deny` when the filtered list is empty (`:367`), deletes `permissions` when the map is empty (`:379`), deletes `hooks` when `rawHooks` is empty (`:391`). `factoryaidroid/hooks.go:357-387` is the same code.

Today, uninstalling in a repo whose `.claude/settings.json` is `{"hooks": {}, "permissions": {"deny": []}}` (no Entire artifact anywhere) rewrites it to `{}`. Under `changed`-gated writes it is left alone.
**Loses something?** Nothing a user can perceive. Empty `hooks: {}` and `deny: []` are valid, inert, and were most likely written by the user or by another tool, not by us. Claude Code does not reject them.
**Should it count as `changed`?** **No.** Counting it would make `AreHooksInstalled` return true for `{"hooks":{}}` — i.e. `entire status` would list Claude Code in any repo with an empty hooks stanza, and `entire disable --uninstall` would stop reporting "not installed" there. That is a much worse false positive than the cosmetic loss. Set `changed` only from: an Entire hook entry dropped from one of the 6/7 managed types, or the `metadataDenyRule` dropped from `permissions.deny`. Then keep the pruning as an *effect* of the write rather than a trigger for it.
**Watch out for:** the prune currently also runs when `changed` *is* true, which is what makes `TestUninstallHooks_RemovesDenyRule` (`claudecode:374`, `factoryaidroid:547`) read a permissions object that no longer exists via `readPermissions`. Keep the prune inside the pure function's write branch, not outside it.

## C3. claudecode / factoryaidroid swallowed `permissions` parse error
`claudecode/hooks.go:341-346`, `factoryaidroid/hooks.go:335-340`: `if err := json.Unmarshal(permRaw, &amp;rawPermissions); err != nil { rawPermissions = nil }` and the cleanup is skipped silently.

Today this is a hidden uninstall bug (the deny rule survives, uninstall reports success). Under the new design it becomes an **advertised lie**: `AreHooksInstalled` would return `false` for a config that still has the deny rule under an unparseable `permissions`, and `getAgentHookState` would classify it as "cleanly reported no hooks" instead of `unchecked` — losing the warning path at `setup.go:2760-2763`. Fix in this change: return an error from the pure function rather than nil-ing `rawPermissions`. See B1.

## C4. cursor / copilotcli top-level `version: 1`
Written on install (`cursor/hooks.go:76-82`, `copilotcli/hooks.go:63-69`), never removed on uninstall.
**Loses something?** No. Today uninstall re-marshals and rewrites the file even when it changes nothing, so a `{"version":1}`-only file gets a pointless write. Skipping it is strictly better.
**Should it count as `changed`?** **No, emphatically.** Counting it would (a) break `cursor/hooks_test.go:235`, `cursor:499`, `copilotcli:157`, `copilotcli:393` — every "false after uninstall" assertion, since `version` survives — and (b) make a leftover `{"version":1}` file mean "Cursor is installed" forever, including in `copilotcli.DetectPresence` (B13). Keep `version` unowned.

## C5. codex's early return on a missing `hooks` key
`codex/hooks.go:186-188`: `if rawHooks == nil { return nil }` — no write. Already equivalent to `changed=false`; map it straight across. Note codex is the only one of the six with this early-out, so it is the existing precedent for the design.

## C6. Repo-root fallback divergence (small but real)
The six agents currently disagree on the `paths.WorktreeRoot` failure fallback: install uses `os.Getwd()` in claudecode (`hooks.go:69`), geminicli (`hooks.go:48`), codex (`hooks.go:70`); uninstall/detect uses `"."` everywhere (`claudecode/hooks.go:284`, `geminicli/hooks.go:308`, `codex/hooks.go:165`, `cursor/hooks.go:200`, `copilotcli/hooks.go:173`, `factoryaidroid/hooks.go:277`). Functionally identical (both resolve relative to the process cwd), so unifying on `"."` in the shared helper is safe and avoids the `//nolint:forbidigo` that `os.Getwd` needs in this codebase. Just don't unify on `os.Getwd()`.

## C7. The two entry points must not diverge on *ordering*
`AreHooksInstalled` and `UninstallHooks` sharing `removeEntireArtifacts` means detection now pays the full parse+transform cost of a removal, per agent, on every sweep. `getAgentHookState` runs on **every command** via `root.go:83` (telemetry) and on every `status`/`review`/`investigate`/`enable`. There is a benchmark guarding the enable hot path (`bench_enable_test.go`) but not the sweep. Six raw-map round-trips per invocation is still microseconds — worth a note, not a redesign, but do not let the helper also *write* from the detect entry point (the "reports `changed`" entry must be provably read-only, same bar `HookFreshness` sets at `agent/agent.go:161-163`).

## C8. `pi` violates the new invariant and is exempted
`pi/hooks.go:108-118` does `os.RemoveAll(filepath.Dir(path))`. So "removal would change this config" is true whenever the extension **directory** exists, including when it holds only a foreign `index.ts`; but `AreHooksInstalled` (`pi/hooks.go:128-143`) keys on `entireMarker` in the file. Leaving pi alone is the right call — widening it would make the sweep call an `os.RemoveAll` over a directory Entire does not own — but it means the new definition is a convention, not an invariant, and the doc comment on `agent.HookSupport` should say so rather than assert it universally. See D3.

# D) The three known asymmetries under the new definition

**D1. geminicli leaves `hooksConfig.enabled: true` (`geminicli/hooks.go:96`, written by install; absent from uninstall at `:304-402`).**
**Stays cosmetic and out of scope** — and must be *kept* out of scope: it is a top-level Gemini setting, not under `hooks`, and Gemini tolerates it with no hooks present. Counting it as owned would pin `AreHooksInstalled` to `true` forever after uninstall, breaking `geminicli/hooks_test.go:387` and permanently listing Gemini in `entire status`. Distinct from `hooks.enabled` (C1), which is inside `hooks`, breaks Gemini's schema, and *is* removed by uninstall — that one becomes a correctness question and my recommendation is to count it.

**D2. cursor + copilotcli leave `version: 1` (`cursor/hooks.go:76-82`, `copilotcli/hooks.go:63-69`).**
**Stays cosmetic and out of scope.** Must not count as `changed` (C4). The only new visible effect is a *good* one: uninstall stops rewriting a file it does not change.

**D3. pi's uninstall `os.RemoveAll`s the extension dir while install refuses foreign files (`pi/hooks.go:108-118` vs the marker check at `:128-143`).**
**Becomes a stated exception rather than a correctness problem** — because pi is excluded, `AreHooksInstalled` stays marker-gated, and every path that can trigger removal (`setup.go:1596` `entire agent remove`, `setup.go:636`/`1661` deselect, `setup.go:2734` uninstall sweep) is gated on that same marker check, so a foreign-only directory is never reached. It does, however, make pi the counterexample to the invariant the design is trying to establish, so the contract comment at `agent/agent.go:124-133` should be written as "for the JSON-config built-ins" rather than "for every agent", and the `os.RemoveAll` blast radius deserves its own follow-up (narrow it to the marker-carrying file plus a directory removal only when the directory is then empty).
