When `gh` is missing or unauthenticated, `configureBranchProtected` (called at line 168) fails and `protected` silently defaults to `false` instead of "unknown" — this is exactly the common case for CI/agent sandboxes, the target environment for `--yes`. Combined with `defaultConfigureSaveChoice` (picks `configureSaveDirect` whenever changes exist, a push is required, and `protected` is false), a fresh non-interactive `entire configure --yes` run (e.g. a freshly cloned repo on `main`, first-time agent selection, clean tree, no unpushed commits) will commit `chore: configure entire` and `git push` straight to the checked-out branch with zero confirmation — there is no non-interactive way to force local-only save instead. Consider treating an unknown/undetectable protection status as protected (favor `configureSaveNewBranch`) rather than defaulting to `false`.
