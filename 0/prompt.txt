### 2. Does list filter by status? Yes — default excludes drafts
The default status filter is `open`, set at `/Users/gtrrz-victor/wks/cli/exploring-entire/cmd/entire/cli/trail_cmd.go:32`:

```go
defaultTrailListStatus = string(trail.StatusOpen)
```

Wired into the `--status` flag default at `trail_cmd.go:414-415`:

```go
cmd.Flags().StringVar(&amp;opts.Status, "status", defaultTrailListStatus,
    "Filter by comma-separated status(es): "+formatValidStatuses()+"; use '"+trailListStatusAny+"' for all statuses")
```

**The filtering is server-side (a query param), not client-side.** Confirmed by:
- The comment at `trail_cmd.go:456-458`: "Filtering, sorting (updated_at desc), and truncation all happen server-side..."
- `trailListQueryWithOffset` at `trail_cmd.go:524-544` builds the `status` query param:

```go
if len(statusFilters) &gt; 0 {
    parts := make([]string, len(statusFilters))
    for i, status := range statusFilters {
        parts[i] = string(status)
    }
    q.Set("status", strings.Join(parts, ","))
}
```

So a bare `entire trail list` sends `?status=open&amp;limit=10`, and the server returns only open trails — drafts never come back to the client.

### 3. Flag to include drafts
Yes. Two ways via the single `--status` flag (there is no `--all` or `--draft` flag):
- `--status any` — disables the status filter entirely (returns all statuses). Constant at `trail_cmd.go:34` (`trailListStatusAny = "any"`); handled in `parseTrailStatusFilter` at `trail_cmd.go:572-575`:

```go
if filter == "" || filter == trailListStatusAny {
    return nil, nil
}
```
(returning empty filters, which omits the `status` param — see the `len(statusFilters) &gt; 0` guard above).
- `--status draft` (or a comma list like `--status draft,open`) — explicitly requests drafts.

### 4. Exact code that sets the default excluding drafts
