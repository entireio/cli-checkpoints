### 2. Should all three call sites use the same predicate, and is one pre-switch guard safe? — Yes to the same predicate; yes to one guard, but it must be a positive list, not a blanket check.

A blanket `if sessionID == ""` before the switch is **not safe**. `entire_extension.ts:136-138` fires `session_shutdown` with `{ type: "session_shutdown" }` and nothing else — no `cwd`, no `session_file`, no `session_id`. So `sessionID` is `""` for *every* shutdown, including the user's own, and a blanket guard would skip `clearCachedSessionID` and fail the existing `TestParseHookEvent_SessionShutdown_ClearsCache` (`lifecycle_test.go:123-152`).

The safe single-guard form, which I verified passes tests and lint:

```go
// A Pi subagent is a nested `pi --no-session` process that auto-discovers this
// same project-local extension, so it fires these hooks with no session of its
// own; the session-ID cache is one per-repo file, so resolving such a payload
// against it hands the child its parent's ID. See docs/architecture/agent-guide.md.
// session_shutdown is exempt: it carries no session identity at all and must
// still clear the cache.
switch hookName {
case HookNameSessionStart, HookNameBeforeAgentStart, HookNameAgentEnd:
    if sessionID == "" {
        logging.Debug(ctx, "pi: skipping hook for sessionless (nested) Pi invocation",
            slog.String("hook", hookName))
        return nil, nil //nolint:nilnil // no session to track = no lifecycle event
    }
}
```

Side note relevant to the design: this is also why the TypeScript guard is **not** redundant with the Go guard.
