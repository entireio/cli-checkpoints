func runGitClone(ctx context.Context, cmd *cobra.Command, cloneURL, targetDir string) error {

For natives, `RepoResolution.Primaries` / `RepoIndexEntry.Primaries` (`api/corev1/repos.go:394-407`):

## 4. `entire://` vs HTTPS — where the scheme is handled

**`entire://` is a client-side Git remote helper only.** There is no server-side `entire://` listener.

- ADR `docs/adrs/20260119-custom-git-remote-transport.md` — decision to replace the credential helper with `git-remote-entire`; *"Git discovers the transport by looking for `git-remote-entire` in `$PATH`"*; trade-off noted at line ~52: *"Non-standard URL scheme (while `https://` URLs still work, you need to construct them manually)"*.
- `README.md:260` — the helper handles auth using the JWT from `entire login`.
- Flow diagram `docs/git-flows.md:21-73`.

**The server speaks plain Git smart HTTP over HTTPS.** Mounts in `server/githttp/service.go:204-214`:
```go
mux.Handle("/et/",  gitAuth(userRateLimit(http.HandlerFunc(svc.handleRepo))))
mux.Handle("/git/", gitAuth(userRateLimit(http.HandlerFunc(svc.handleRepo))))
mux.Handle("/gh/",  gitAuth(userRateLimit(http.HandlerFunc(svc.handleRepo))))
```
`handleRepo` (`server/githttp/repo.go:110-160`) canonicalizes then resolves via `repo_urls.LookupByPrefix` (`:133-134`), longest-prefix match (`repourls/store.go:189-232`).

Proof HTTPS works directly: `test/objectformat_e2e_test.go:235-237` builds `https://&lt;node&gt;/et/&lt;owner&gt;/&lt;repo&gt;` and clones it with `-c http.&lt;url&gt;.extraHeader=Authorization: Bearer …` (`:181-182`); `test/workloads/git_workflow.go:95` clones `http://test/et/&lt;user&gt;/&lt;repo&gt;` with basic auth. Also `core/api/mirrors.go:1013-1014` returns **both** forms on mirror create:
```go
MirrorURL: "entire://" + clusterHost + url,
PublicURL: publicURL + url,      // "https://&lt;cluster public url&gt;" + "/gh/owner/repo"
```

### ⚠️ The `.git` suffix in your proposed URL is a bug

Your plan says `git clone entire://aws-ap-southeast-2.entire.io/et/paul/dogbark.git`. **`.git` stripping is `/gh/`-only.**

`core/authn/audience.go:332-344`:
```go

	...

```

...

Plus `core/authn/audience_test.go:33`: `{"/et/acme/widgets.git", "/et/acme/widgets.git"}`.

**Correct URL: `entire://aws-ap-southeast-2.entire.io/et/paul/dogbark`** (no `.git`). Note git will then name the working directory `dogbark`, which is what you want anyway.

### The host must be a real placement host (STS enforces it)

## 6. `paul` is a **project name**, not an org or a user

- `/et/&lt;project&gt;/&lt;repo&gt;` — `core/coreapi/repos.go:158-161` and `core/authn/audience.go:20`: `https://&lt;entiredb-host&gt;/et/&lt;project&gt;/&lt;repo&gt;`.
- Project names are **globally unique**, enforced by `core/resource/migrations/016_projects_name_global_unique.sql:2` (`CREATE UNIQUE INDEX projects_name_key ON projects (name)`) plus the case-folding index `023_projects_lower_name_unique.sql:11` (`lower(name)`).
- ADR `docs/adrs/20260522-global-project-names.md`: *"Project names are globally unique, immutable, human-readable identifiers… 3–32 characters, `[a-z0-9-]`, no leading or trailing hyphen. Raw ULID-shaped strings are rejected so the CLI resolver can fast-path ULIDs without a server round-trip."* And: *"No cross-resource reservation: project names are not reserved against org names, account handles, repo URL owners, mirror paths, or reserved words."*
- Shape enforced at `core/resource/project_name.go:10-34` (`projectNameMinLen=3`, `projectNameMaxLen=32`; `foldProjectName` lowercases for lookup).
- A project is owned by either an **org or an account** — `Project.OwnerType` enum `org,account` (`api/corev1/projects.go:11`). So `paul` is very plausibly an account-owned personal project named after the handle (cf. `test/workloads/git_workflow.go:95` → `/et/&lt;username&gt;/&lt;repo&gt;`), but the path segment is unambiguously the **project name**.
- **API addressing**: paths use ULIDs (`GetProjectInput.ProjectID` `pattern:"^[0-9A-HJKMNP-TV-Z]{26}$"`, `api/corev1/projects.go:53`). Name→ULID resolution is `GET /api/v1/projects?name=&lt;name&gt;` (`api/corev1/projects.go:36`, single-project response at `:46`). Server-side the anonymous lookup uses `res.GetProjectByName` (`core/coreapi/repos.go:3501`).
- Repo-within-project lookup is by **repo_group full_name** = `"&lt;project&gt;/&lt;repo&gt;"`: `GetRepoGroupByProjectAndFullName(ctx, project.ID, projectName+"/"+repoName)` (`core/coreapi/repos.go:3510`, and `:3002` for the authenticated arm). This can return `resource.ErrAmbiguous` → **409** when two upstreams share a short name in one project (`:3515-3521`) — worth surfacing in the CLI rather than swallowing.

## Recommended resolution path for `entire clone /et/paul/dogbark`

1. Parse with the existing `internal/clidial/parse.go:23` shape (accept `/et/p/r`, `et/p/r`, `host/et/p/r`, and full `entire://` URLs).
2. `POST /api/v1/repos/resolve` `{"repositories":[{"provider":"entire","fullName":"paul/dogbark"}]}` → `repoId`, `placements[]`, `primaries` (one round-trip, authz-correct, read-token-friendly).
3. Pick the home placement: `primaries.data_primary.repo_id` (falling back to `primaries.processing`, then the single non-mirror placement) — mirrors `core/coreapi/repos.go:3533-3539`.
4. Turn `clusterSlug` into a git host — either `GET /api/v1/repos/{repoId}` (gives `clusterHost` **and** `path`, one extra hop, and `path` is authoritative rather than reconstructed) or `GET /api/v1/clusters` (cacheable slug→`publicUrl` map, then build `/et/&lt;project&gt;/&lt;repo&gt;` yourself).
5. Build `entire://` + host + path — **no `.git` suffix** — and shell out to `git clone`.
