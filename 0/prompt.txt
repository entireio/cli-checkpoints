- [P2] A nested no-env agent can still adopt an outer agent’s session silently — cmd/entire/cli/session_adopt.go:212
   With no environment claims, HasAncestor treats any matching ancestor as uncontested. Consider OpenCode launching Gemini, with both
   sessions stored in the source repository while the command runs from a separate target repository. The target-only resolver sees
   neither state; explicitly selecting OpenCode’s outer session passes HasAncestor, although Gemini’s owner is nearer. Resolve against
   all relevant source and target states together—or otherwise require the selected source owner to be the nearest recorded
   owner—instead of checking only whether it appears anywhere in the ancestry.
