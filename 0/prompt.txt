## Q1 — Hot-path cost: fast path is cheap; one configuration is not

Benchmarked in a real repo with the `WorktreeRoot` cache warm (M4 Pro, 2000 iters):

| state | per gate call |
|---|---|
| un-set-up repo, no global file (**every user today**) | 6.8 µs (old predicate: 12.1 µs — delta is noise) |
| repo **is** set up | unchanged code path |
| global mode on, no `exclude_origins` | 21.7 µs |
| global mode on **with** `exclude_origins` | **10.9 ms** |

The fast path stays cheap for a structural reason worth recording: `IsSetUpAny` → `paths.AbsPath` → `paths.WorktreeRoot` already warms the per-process cwd-keyed cache before `GlobalModeActive` needs it, so the global tier adds **no** extra `git rev-parse` fork on any route. In dark launch the entire added cost is one ENOENT `os.ReadFile`.

The outlier is `exclude_origins`: `gitremote.GetRemoteURLInDirIfSet` forks `git config --get` with no caching, ~500× the fast path, and it runs on **every** gate evaluation. See Important #1.

## Issues

### Important

**1. `exclude_origins` makes each gate evaluation a ~11 ms fork; ×2 per hook invocation ≈ 22 ms — needs memoization before `enable --global` ships.** `settings/global.go:188` (via `gitremote.go:110`).
Not a blocker for *this* commit — nothing writes the global settings file yet, so the path is unreachable in the dark-launch state, exactly as the commit message claims. But hooks fire on every prompt and every tool event, so once `enable --global` lands this is ~22 ms of pure `fork`/`exec` per event for any user who configures origin excludes. Memoizing `GlobalModeActive` per process is the natural fix and has no invalidation problem, since hooks are one-shot processes (`sync.OnceValue` or a package-level memo). Recommend tracking it explicitly against PR 3 rather than as a general "optimize later", because it becomes user-visible latency the moment the writer command exists.

### Minor

**2. The double-read makes the gate non-atomic, which is the stronger argument for the same memoization.** `hooks_git_cmd.go:172` + `:183`.
Two reads of a mutable file within one invocation can in principle disagree (a concurrent `entire disable`, or the global file being rewritten between the two calls), which is precisely the split-gate condition this commit set out to eliminate. Memoizing closes the correctness gap and the cost gap together — worth folding into #1's rationale rather than filing separately.

**3. "Defense-in-depth" is inverted on the agent-hook route — `hooks_git_cmd.go:131-132`.**
The comment says the `initHookLogging` check is defense-in-depth, "also checked in PersistentPreRunE". True for git hooks. But on `hook_registry.go:65`, `initHookLogging` runs *inside* `PersistentPreRunE`, before `executeAgentHook`'s gate at `:123` — so on that route it is the **primary** gate, not the backup. Doesn't change behavior (both use one predicate now), but the comment misdescribes the ordering for two of the three routes.

**4. The new test shells out to bare `git init` — `hooks_git_cmd_test.go:184-188`.**
No `testutil.InitRepo`, no isolated git env, and `context.Background()` instead of `t.Context()`, against CLAUDE.md's explicit rule. Mitigating: it is a verbatim clone of its two immediate neighbors (`:113-122`, `:145-150`), and none of the three ever commits, so the identity/GPG rationale behind the rule doesn't actually bite. Better handled as one cleanup pass over all three than by singling out the new one. Also `0o644` on the settings file where `settings/global_test.go` uses `0o600` — trivial.

**5. Q3 — cleanup is safe, but the residue is process-global rather than filesystem.**
`.entire/logs` is under `t.TempDir()`, and `cleanup()` runs at `:202` before `RemoveAll`, closing the fd first — so no artifact, and no Windows removal block either. The subtler point: `logging.Close` (`logging/logger.go:145-158`) flushes and nils `logBufWriter`/`logFile` but leaves the package-level `logger` non-nil, still holding a handler wrapping the now-closed writer. So after this test the `cli` package's global logger points at a dead writer for the rest of the run. Benign — slog discards write errors and nothing in the package asserts on log output — but this is the **first** test in the file to make `logging.Init` succeed (its neighbors assert the no-op path), so it is the first to leave that residue. `resetLogger()` exists at `logger.go:161` but is unexported and in another package, so there is no clean fix from here; recording it is enough.

**6. The assertion doesn't cover the privacy-relevant half of the motivation.** `hooks_git_cmd_test.go:205-208`.
The commit justifies converting this gate partly because global-mode repos otherwise never call `strategy.EnsureRedactionConfigured()`. The test proves `.entire/logs` exists, which is a fine proxy for `logging.Init`, but it would still pass if the `EnsureRedactionConfigured()` call at `hooks_git_cmd.go:151` were deleted.

## Behavioral edges checked and clean

- **A set-up repo can never fall through to the global tier from a subdirectory.** This was my main correctness worry, since a false `IsSetUpAny` now means "consult the global tier" instead of just "inactive". `paths.AbsPath` (`paths/paths.go:112-123`) resolves against `WorktreeRoot`, not cwd, so `IsSetUpAny` finds the root `.entire/settings.json` from anywhere in the tree. No mis-fire.
