### 6. `cmd/entire/cli/strategy/hooks.go:466` / `settings/settings.go:969` — the residual `absolute_git_hook_path` path is much weaker than the one removed, and the invariant is already half-pinned
`absolute_git_hook_path` is still merged from the committed project file and still reaches `hookCmdPrefix`. But it only selects between `"entire"` and `shellQuote(os.Executable())` — the path of the binary already running. A repo cannot use it to make a hook execute repo content, so the security invariant ("hooks never run tracked content") is intact; what survives is a repo influencing the *form* of the command. Worth saying that plainly in the PR rather than leaving reviewers to re-derive it.

The diff also already added the right *kind* of structural guard: `TestGitHookCommand_GuardsEveryInstallablePrefix` asserts every prefix `hookCmdPrefix` can emit is existence-guarded. The cheap extension is to assert in the same test that the prefix is never repo-relative (`!strings.HasPrefix(p, ".")` / absolute-or-bare-`entire`), which converts the doc comment at `hooks.go:466` into something enforced. **In-scope now**, ~4 lines.

### 7. `cmd/entire/cli/settings/settings.go:68` — deprecated-field approach is the right depth, with one asymmetry to note
It matches existing house precedent (`Strategy` at `:165`, `Review`/`ReviewFixAgent` at `:178-182` — all deprecated no-op fields kept for `DisallowUnknownFields` tolerance), so no new mechanism is warranted here. One inconsistency: the base-file struct decode (`loadFromFile`) **does** still populate `LocalDev` from the committed `.entire/settings.json`; only `mergeScalarFields` skips it.
