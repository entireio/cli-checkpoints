`SuppressAdditionalSetup` causes `runEnableInteractive` to skip the telemetry block entirely, leaving `settings.Telemetry` as `nil`. Every downstream consumer (`root.go`'s `telemetryEnabled != nil && *telemetryEnabled`, `plugin.go`'s `s.Telemetry == nil || !*s.Telemetry`, `checkpoint_policy_telemetry.go`) treats `nil` as opted-out, so new users onboarded through this new default `entire configure` flow silently end up with telemetry disabled instead of the documented default-enabled behavior (`--telemetry` flag defaults to `true`). Login establishing account context is unrelated to this repo-local anonymous-analytics flag, so the stated rationale doesn't justify skipping it for first-time setups.

The save step should be present, not just after making a selection in the second section.
