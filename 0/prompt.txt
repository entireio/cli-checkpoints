One new issue, same class as the one just fixed

plugin_index.go is an unchecked consumer of userdirs.Cache(). With a relative XDG_CACHE_HOME, SyncPluginIndex does os.MkdirAll(filepath.Dir(dir), 0o750) at line 197 and takes a flock at line 201 — both landing in the working directory — before osroot.Shared(dir) at line 210 refuses it. That's exactly the "creates the thing on the way to reporting the error" pattern the PR just fixed in three other places.

Related: Config()'s rewritten doc comment now says "there are four" consumers and enumerates them. Enumerating consumers in prose is what let tokenstore slip the first time; this is the second miss on the cache side.

Two smaller things

Doc comment got hijacked. var errSelectionNotPersistable was inserted between autoSelectSummaryProvider's doc comment and the function (explain_summary_provider.go:183-191). The function is now undocumented, and the var's comment opens by describing the function. Clearly accidental; lint won't catch it.

The vouched-symlink feature is process-global mutable policy. settings.Load calls agent.SetVouchedSymlinkedDirs, which writes a package global. AnchorWorktreePath takes a worktreeRoot argument but consults that global, so the policy isn't bound to the worktree it came from — last load wins. No path I can find exploits this today (agent-config writes are all current-worktree), so it's a coupling worth naming rather than a bug. Slightly ironic given the commit message's own argument that the vouchable set must be pinned because a runtime-mutable registry is the wrong thing to build a boundary on.
