## Verdict

The core design is efficient and I want to say that plainly before the nits: the expensive work (`opencode --version`, `npm install`, the 61MB tree) is behind `sync.OnceValues` and happens once per process; the per-repo path is ~7 syscalls and a symlink. There is no per-repo re-computation of anything expensive, no sequential work that wants to be concurrent, and `sync.OnceValues(buildPluginDeps)` wraps a top-level func with **no captured scope**, so there is no long-lived closure holding anything.

Three real-but-small findings, best first. None is large; I am not going to inflate them.

---

### 1. `e2e/agents/opencode.go:66` + retry loop at `:166-183` — the raised warmup budget is multiplied by 3 retries, on exactly the failure path this diff exists for

The budget went 30s → 90s and the loop still makes 3 attempts with 5s sleeps, then gives up non-fatally (`"proceeding anyway"`, line 185). On the success path this costs nothing (attempt 1 returns in seconds). On the hang path — the 2026-09-03 scenario the diff targets — bootstrap now blocks for **up to ~280s instead of ~100s** before proceeding anyway and letting all ~40 tests run regardless.

Cheaper: 2 attempts instead of 3 at the raised budget (saves up to 95s), or keep 90s only for attempt 1 and drop later attempts back to ~30s. Concrete cost: **+180s of blocked CI time per opencode leg, once per run, only when the warmup is already hanging.**

The stated justification for 90s ("a budget that kills the attempt part-way leaves that work half-done") argues for the first attempt's length; it does not argue for paying it three times before shrugging.

### 2. `e2e/agents/opencode.go:268-276` — `package.json` and `package-lock.json` are re-read from the shared tree on every `SeedRepo` call

`openCodePluginDeps()` returns only the directory, so each of the ~40 calls does `os.ReadFile` on the same two files and writes the bytes back out.

Cheaper: have `buildPluginDeps` return a small struct (`dir string; pkgJSON, lockJSON []byte`) and have `sync.OnceValues` memoize the contents alongside the path — the read then happens twice per process instead of ~80 times. (Symlinking these two the way `node_modules` is symlinked would be wrong: opencode generates/rewrites `.opencode/package.json`, so a link would write back into the shared tree.)

Concrete cost: **78 redundant reads of a 13.5KB lock file plus a ~100-byte package.json — well under a megabyte, page-cached, sub-millisecond in aggregate.** It is genuine repeated I/O in the hot path and it is a two-line fix, but I am not going to claim it costs anything measurable.

### 3. `.github/workflows/e2e.yml:152-156` — the whole opencode log dir is copied and uploaded unpruned

`cp -R "$HOME/.local/share/opencode/log/."` takes every log file the runner has, and opencode writes one per process — the diff's own comment counts 53 opencode processes in a leg, before scenario restarts.

Cheaper: prune to the run's own logs, e.g. `find "$HOME/.local/share/opencode/log" -type f -newermt '-2 hours'` piped into the copy, or cap it (`ls -t | head -60`).

Concrete cost: **once per opencode leg; roughly 15-50MB of extra copy + zip + artifact upload** depending on log verbosity. This is the step's whole purpose, so it is a trim, not waste — I rank it last for that reason.
