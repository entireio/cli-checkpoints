Filed here as notes, not findings — neither is exploitable and I would not block the PR on either.

1. The on-demand prompt does not name its source. "Install the entire-graph plugin?" (plugin_on_demand.go:56) defaults to Yes and never shows the resolved repo URL, unlike confirmInstallOrCancel, which names redactURL(repoURL) and defaults to No. It is the only human checkpoint before a remote binary is downloaded and executed. No marginal escalation exists (anyone who can set ENTIRE_PLUGIN_INDEX_URL can equally drop a binary on $PATH, which prompts for nothing), but adding the repo URL to the prompt line would cost nothing and make the one new unprompted-command-to-exec path self-describing.
2. A doc inaccuracy with a security-adjacent claim. docs/architecture/external-commands.md states "EOF declines". That is true in accessible mode; in the default bubbletea path an EOF makes the prompt block until cancellation. The behaviour is fail-closed either way — a hang, never a silent Yes — so this is doc accuracy rather than a vulnerability, but the sentence currently promises a guarantee the default path implements differently.
