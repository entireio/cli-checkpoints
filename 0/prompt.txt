- alternative: `git ls-files --others --exclude-standard` (or `git status --porcelain -z -uall`) run at the worktree root. **Zero signature changes, one function body**, and the codebase already establishes the pattern twice for exactly this reason: `getStagedFiles` (`manual_commit_hooks.go:2550-2557`: "much faster than go-git's `worktree.Status()` which scans the entire working tree") and `collectChangedFiles` (`cmd/entire/cli/checkpoint/ephemeral.go:1238`, "modified tracked + untracked non-ignored … git CLI … go-git's `worktree.Status()` does not respect global gitignore"). ## How invasive is threading a `git.Status` through? (question 3)

Cheaper than it looks, because **there is no `Strategy` interface** — `grep '^type .* interface'` across `cmd/entire/cli/strategy/*.go` returns nothing, and `GetStrategy` (`cmd/entire/cli/config.go:68`) returns the concrete `*strategy.ManualCommitStrategy`. So `InitializeSession` is a concrete method with **one** production caller. (Note: `CLAUDE.md` still describes a `Strategy` interface in `strategy.go` — that doc is stale, independent of this diff.)

The `cli → strategy` boundary is **not** awkward: `git.Status` is an exported go-git type already imported by both packages (`cmd/entire/cli/state.go:23`, and `strategy` throughout), and the dependency direction is the existing one. No new abstraction, no new import edge.

Signatures to change: 4, across 2 packages.
1. `getUntrackedFilesForState(ctx)` → take a `git.Status` (`state.go:430`). 2 prod callers — but `CapturePreTaskState` (`state.go:494`) is on the ToolUse path and needs its own read, so keep a thin reading wrapper.
2. `CapturePrePromptState(ctx, ag, sessionID, sessionRef)` → + `status git.Status` (`state.go:98`). 1 prod + 3 test callers.
3. `(*ManualCommitStrategy).InitializeSession(...)` → + `status git.Status` (`manual_commit_hooks.go:2274`). 1 prod caller + **~41 test call sites across 8 files** (`phase_wiring_test.go` alone has 18; also `manual_commit_staging_test.go`, `agent_resolution_test.go`, `phase_prepare_commit_msg_test.go`, `manual_commit_test.go`, `owner_wiring_test.go`, `manual_commit_concurrent_test.go`, `session_adopt_test.go`).
4. `calculatePromptAttributionAtStart(ctx, repo, state)` → + `status git.Status` (`manual_commit_hooks.go:2443`). 3 in-file callers.

Realistic verdict: ~4 signatures and ~45 call-site edits, of which ~90% is mechanical test churn, to save ~34 ms (~120 ms on a large tree). The churn can be cut to near zero by accepting a nil `git.Status` and having the callee fall back to `gitrepo.Status(ctx, repo)` — but that reintroduces a "did someone pass me a stale snapshot?" contract at every hop, which is the same class of hazard the cache was deleted to remove, just spread across four signatures instead of one context value.

**Recommendation, in order:** finding 2 (comment, must fix), then finding 4 (native git for the untracked snapshot — removes one walk with zero threading and two in-repo precedents), then finding 3 (local split, removes the reconcile duplicate). Full `git.Status` threading (findings 1/5) is the option I'd *not* take: it buys the same ~34 ms that finding 4 buys for one function body, at 45 call sites and a new stale-snapshot contract.</result>
