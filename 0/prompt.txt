1. `entire search --json --compact "&lt;query&gt;"` (never bare `entire search` — it opens the TUI).
2. Scan compact hits: `id`, `filesTouched`, `score`, `snippet`, truncated `title`. Prefer checkpoint/commit hits; session hits are projections.
3. `entire checkpoint explain &lt;id&gt;` — the compact `id` is the checkpoint ID or commit SHA and feeds `explain` directly. Session hits bridge via `entire checkpoint explain --session &lt;id&gt;` (lists that session's checkpoints, then explain one).
4. `--full` for the whole transcript only if scoped detail is insufficient.
5. Narrow and re-search rather than explaining many hits.

Identifier plumbing: `Result.ResultID()` (`search.go:345`) returns checkpoint `id` / commit `commitSha` / session `sessionId` / raw `id` for repo+pr; that's what `--compact.id`, the static table's ID column (`formatResultID`, `search_tui.go:1237`, commits shortened to 7 chars) and the TUI detail "ID" row print. Checkpoint and commit IDs feed `explain` verbatim; the cross-repo case needs `--repo owner/name` plus a **full** ID.
