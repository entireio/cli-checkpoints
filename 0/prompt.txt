## Important

**1. The case-fold test is a tautology and cannot fail — `global_test.go:102`.**
```go
{"case fold on case-insensitive filesystems", []string{"/TMP/Scratch/**"}, "/tmp/scratch/x", caseInsensitivePaths},
```
The expected value *is* the variable the implementation branches on, so the assertion reduces to `flag == flag`. **Proven by mutation**: rewriting `global.go:26` to `runtime.GOOS == "linux"` — which would disable folding on exactly the two platforms it exists for — still passes every subtest on darwin. Fix 3's production code is correct, but it currently has zero regression protection. Cheapest fix is a literal expectation independent of the production var (`runtime.GOOS == "darwin" || runtime.GOOS == "windows"`); better is a `matchesExcludePathFold(fold bool, …)` seam so both branches are exercised deterministically on every platform.

## Minor

- **Multi-URL origins are matched against the wrong URL — `gitremote.go:110-129`.** Empirically, with two `remote.origin.url` lines, `git config --get` exits 0 and returns the **last** value, whereas `git remote get-url` returned the **first**. For an *exclusion*, the safe semantics are "exclude if **any** configured URL matches"; `--get-all` plus a match-any loop would give that. Narrow (multi-push origins are uncommon) but the failure direction is open.
- **The exit-1 doc comment slightly overclaims — `gitremote.go:114-116`.** It says exit 1 means "exactly 'key not present'". Git also returns 1 for an invalid key name (verified: `git config --get "remote.o rigin.url"` → exit 1). Harmless for the hardcoded `"origin"`, but this is now an exported general-purpose helper, so a caller passing a malformed `remoteName` silently gets `found=false` instead of an error.
- **The empty-pattern skip guard was quietly defeated — `global.go:112-116`.** `filepath.Clean("")` returns `"."`, so `expandTilde("")` now yields `"."` instead of `""` and no longer trips the `expanded == ""` branch. Still safe — I verified `Match(".", root)` and `Match("./**", root)` are both false for absolute roots — but an empty entry is now silently inert with no debug line, which is the diagnosability hole fix 5 was meant to close. Same applies to any relative pattern.
- **`Clean` also resolves `..` inside patterns.** `/tmp/a/../**` now matches `/tmp/b/x` (verified), where previously `..` was a literal segment. Direction is fail-closed (over-excluding), and it's arguably what the user meant, but it is a semantic change beyond trailing slashes.
- **`GlobalModeActive` still swallows the settings *read* error unlogged — `global.go:180-182`.** `LoadUserSettings` logs only the parse branch, so a mode-0000 `~/.config/entire/settings.json` deactivates global mode with no debug line at all.
- **Remaining test gap: the composition of fix 1 is untested.** Both halves are covered (the helper errors; `GlobalModeActive` has a `!found` → active test), but nothing pins "origin lookup error → global mode inactive". Genuinely awkward without a seam, since `paths.WorktreeRoot` fails first in most broken-git scenarios — reasonable to skip for a four-line branch, but worth a deliberate decision rather than an oversight.
