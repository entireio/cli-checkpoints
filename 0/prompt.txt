## Verdict on the deliberate hotspot: appropriate suppression, with one diagnosability gap

**`resolveImportLinkCommitSHA` — /Users/peytonmontei/Documents/entire/devenv/entireio/cli/.worktrees/import-commit-link/cmd/entire/cli/import_link.go:15-28**

The design contract is sound. On the error-kinds question: yes, go-git's `Reference`/`Head` conflate `ErrReferenceNotFound` with storage-level failures (unreadable packed-refs, permission errors), and this function cannot distinguish "no such branch" from "repo is broken." ## Findings

**IMPORTANT — No trace of which arm resolved, or why the anchor is empty.**
Location: `import_link.go:15-28` / call site `import_cmd.go:72`.
The function has four outcomes (origin tip, local tip, HEAD, `""`) and records none of them. Failure scenarios a support engineer cannot currently diagnose:
- Imported sessions show no anchor on the web UI → was the repo commit-free? Did every ref lookup fail due to an unreadable refs store? Nothing in `.entire/logs/` answers this.
- Sessions anchored to a months-stale commit → user hasn't fetched, so the `origin/&lt;default&gt;` arm won with a stale tip. Invisible; looks like a server bug.
- `GetDefaultBranchName` returned `""` (branch named `trunk`, no origin), so HEAD-of-a-feature-branch became the anchor. Invisible.

linkSHA := resolveImportLinkCommitSHA(repo)

SHA-only is operational metadata, so it is compliant with the privacy rule.
