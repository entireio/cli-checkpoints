### 3. `HomeJurisdictionFromLoginJWT` and whether it works on env tokens

`/Users/gtrrz-victor/wks/cli/fix-conflicts/cmd/entire/cli/auth/cell_data_api.go:565-581`:
```go
func HomeJurisdictionFromLoginJWT(loginJWT string) (string, error) {
    parts := strings.Split(loginJWT, ".")
    if len(parts) &lt; 2 {
        return "", errors.New("login token is not a JWT")
    }
    payload, err := base64.RawURLEncoding.DecodeString(parts[1])
    ...
    var claims struct {
        HomeJurisdiction string `json:"home_jurisdiction"`
    }
    if err := json.Unmarshal(payload, &amp;claims); err != nil { ... }
    return claims.HomeJurisdiction, nil
}
```

There is no separate env-token home-jurisdiction helper, and none is needed. This function just reads the `home_jurisdiction` claim from any JWT payload. ENTIRE_TOKEN env tokens carry `home_jurisdiction` — confirmed both by the test fixture `/Users/gtrrz-victor/wks/cli/fix-conflicts/cmd/entire/cli/auth/cell_data_api_test.go:553` (`{"aud":"https://us.auth.entire.io","home_jurisdiction":"us",...}`) and by the existing reuse in `resolveJurisdiction` (below), which passes an env token straight into `HomeJurisdictionFromLoginJWT`.

The canonical reuse is `resolveJurisdiction` at `/Users/gtrrz-victor/wks/cli/fix-conflicts/cmd/entire/cli/auth/cell_data_api.go:378-395`: explicit override wins, else `HomeJurisdictionFromLoginJWT(loginJWT)` — and `loginJWT` there is the env token when ENTIRE_TOKEN is set (wired via `resolveCellSubject` → `resolveEnvTokenCellSubject`, cell_data_api.go:219-224 and 328-342). Test at cell_data_api_test.go:580-586 asserts "Empty jurisdiction falls back to the env token's home_jurisdiction claim."

Note the `aud` claim (env_token.go `CoreURLFromEnvToken`) encodes the core *host/origin*, not the jurisdiction label. So do NOT parse `aud` to get the jurisdiction — use the `home_jurisdiction` claim via `HomeJurisdictionFromLoginJWT`.

### 4. `ResolveControlPlaneTarget` and getting the bearer under ENTIRE_TOKEN

`/Users/gtrrz-victor/wks/cli/fix-conflicts/cmd/entire/cli/auth/control_plane.go:47-60` — `func ResolveControlPlaneTarget() (ControlPlaneTarget, error)`. It reads only the active contexts.json context; it has NO awareness of ENTIRE_TOKEN. The struct (control_plane.go:32-35) is:

type ControlPlaneTarget struct {

`TokenSource` is a refreshing login provider bound to the context's core (`targetForContext`, control_plane.go:126-132).

This is exactly why the current `defaultCloneHomeJurisdiction` is wrong: it calls `target.TokenSource(ctx)` which mints/refreshes a *stored-context* login JWT, ignoring ENTIRE_TOKEN entirely. When ENTIRE_TOKEN is set, the bearer a coreapi.Client actually uses is the raw env token itself (see #5), not anything from `ResolveControlPlaneTarget`.

The env-token-aware analog is `resolveAuthStatusTarget`/`resolveEnvTokenStatusTarget` (auth.go, #2), which get the bearer via `auth.ParseEnvToken(raw)` → returns `(coreURL, token)` where `token` is the verbatim bearer.

### Recommended fix pattern for `defaultCloneHomeJurisdiction` (repo_clone.go:543-557)

Mirror `resolveAuthStatusTarget`/`resolveCellSubject`: guard ENTIRE_TOKEN first, extract the jurisdiction from the env token via the existing helpers, else keep the current active-context path. Concretely:

```go
func defaultCloneHomeJurisdiction(ctx context.Context) string {
    if raw, ok := os.LookupEnv(auth.EnvTokenVar); ok {
        _, token, err := auth.ParseEnvToken(raw)
        if err != nil {
            return ""
        }
        jur, err := auth.HomeJurisdictionFromLoginJWT(token)
        if err != nil {
            return ""
        }
        return strings.TrimSpace(jur)
    }
    target, err := auth.ResolveControlPlaneTarget()
    ... // existing fallback unchanged
}
```

This reuses `auth.EnvTokenVar`, `auth.ParseEnvToken`, and `auth.HomeJurisdictionFromLoginJWT` — no new parsing — and preserves the best-effort "return empty on any uncertainty" contract. `os`, `strings`, and `auth` are all already imported in repo_clone.go (os and auth used at lines 336/403, strings at 556/570).
