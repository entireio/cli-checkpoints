`resolveTrailReviewTarget` now routes ID-keyed review/finding requests to the entire-api cell via `SetTrailRoute`, but `trailReviewCommentsPath` and `trailReviewStatePath` still build query strings with the legacy snake_case keys (`include_dismissed`, `limit`, `offset`) instead of the camelCase/cursor convention used elsewhere in this migration (e.g. `trailListPageQuery`'s `pageSize`/`pageToken`, and the `TrailsEnabled` backend-aware query fix in this same branch). If entire-api's findings endpoint expects the same camelCase convention, `entire trail finding list`, `entire trail resume`, and `runner_gather`'s trail-context gathering would silently drop the dismissed-filter and could loop forever in `fetchAllTrailReviewComments` if the server ignores `offset` and keeps returning `hasMore=true`.
