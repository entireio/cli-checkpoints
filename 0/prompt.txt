- `cmd/entire/cli/status.go:429` — **medium.** `if authoritative, fetchErr := ReadsDedicatedStore(...); fetchErr == nil` fail-softs to `dedicated = false`, and the code then names the elected remote as the read source. Reachable: a repo whose only remote is not named `origin` plus a configured `checkpoint_remote` makes `fetchURLAuthoritative` return `no fetch URL found`; status prints `Checkpoints read from: upstream` while real checkpoint reads fail. The push branch's fail-soft is safe because `resolvePushSettings` degrades the same way; the fetch branch's is not. Treat a probe error as unknown (suppress the read line, or surface it) rather than as a resolved remote.
