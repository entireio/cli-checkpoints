OpenHookConfig now stores the post-anchor inner name, but RemoveDir still treats that name as worktree-relative and bails when path.Dir is .. Vouching for .pi/extensions/entire — a listed, followable directory — makes uninstall refuse and leaves the pi extension in place, which pi still discovers.

configRoot now rejects any relative configDir, but its only caller passes userdirs.Config() verbatim, which returns a relative path (e.g. .config/entire) whenever os.UserHomeDir() fails — that fallback is not an override, and userdirs.openUserRoot deliberately absolutizes it instead of rejecting it (see userdirs.go's own doc comment on openUserRoot). Because this comment's doc explicitly frames the check as being about $ENTIRE_CONFIG_DIR, but the code can't distinguish an override from the internal fallback, this call now hard-fails auth/context loading in the no-$HOME edge case that previously worked via filepath.Abs. The same pattern is duplicated in discovery/cache.go's cacheFile.root() for userdirs.Cache(). Consider having userdirs.Config()/Cache() themselves absolutize the fallback case (as openUserRoot does) so downstream RequireAbsoluteOverride checks only ever see genuine overrides.
