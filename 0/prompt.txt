I read the diff and the real files. Verdict up front: **this is a genuine altitude finding, not a nitpick.** The codebase has already decided this exact tradeoff in favor of centralized Kind predicates, and the diff both ignores that convention *and* invents a field that literally names the missing concept. There are two distinct concepts being open-coded across the sites, and at least one of them clearly deserves a method.

### The two concepts hiding in the 5 sites

The checks are not all the same concept — that's the key to getting the depth right:

- **"read-only" (user-facing capability)** — `resume_picker.go:171` (can't resume), `sessions.go:443` ("imported (read-only)" label), `sessions.go:613` (`ReadOnly: state.Kind == session.KindImported`), `sessions.go:661` (info note "read-only").
- **"lifecycle-exempt / not auto-managed"** — `session/state.go:480` (never stale-purged), `strategy/manual_commit_session.go:96` (kept past shadow-branch orphan check), `strategy/cleanup.go:353` (never offered for cleanup).
- **genuinely import-specific** — `resume_picker.go:188` (`countImportedSessions`, whose hint text literally says "imported"). This one legitimately wants the concrete Kind.

### Why the shallow form is a real cost here (not YAGNI)

1. **The codebase already established the pattern.** `session/state.go:73` `Kind.IsReview()` and `:84` `Kind.IsInvestigate()` are *single-equality* predicates (`k == KindAgentReview`) with docstrings explicitly justifying them: "so the umbrella flag stays accurate without string-literal coupling across packages" and "so future review kinds can be added without changing summary-shape." The new imported checks are the same shape (equality on a Kind, consumed across 4 packages) but were written inline instead. That's an inconsistency with an already-decided local convention — the strongest possible argument that the method is wanted here.

2. **The diff already named the concept.** `sessions.go:613` introduces a JSON field `ReadOnly bool` computed as `state.Kind == session.KindImported`. When you're adding a field called `read_only` whose value *is* the predicate, the predicate deserves to be a method. Right now "read-only" is defined in four places (the field, the list label, the info note, the resume filter) and could drift — e.g. resume could start excluding a Kind that the list label still doesn't mark read-only.

3. **Drift surface for the next Kind.** The whole point of the existing `IsReview`/`IsInvestigate` methods is that adding `KindManualReview` touches one line.
