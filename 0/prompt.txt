User's framing: "In Go, Init is not really a thing. The common pattern is having a New(config) and use that object in the caller and pass it thru contexts propagation. ## Current global surface (all five must go)

    logger        *slog.Logger

    logBufWriter  *bufio.Writer

Target shape, roughly — names your call:

    type Config struct { Dir string; Level slog.Level; ... }
    func New(cfg Config) (*Logger, error)

Then: root prerun does `l, err := logging.New(cfg)` → `cmd.SetContext(logging.WithLogger(ctx, l))`; root PostRun does `if l := logging.LoggerFromContext(cmd.Context()); l != nil { l.Close() }`.

## What this deletes beyond the globals

- **`liveWriter` goes.** Its entire purpose was routing writes to whichever buffer the *global* currently held so loggers survived a re-Init. With an instance there's no global to swap and no re-Init. Keep the per-write mutex — bufio.Writer still isn't goroutine-safe and slog handlers can be called concurrently — but as an instance field.
- **`SetLogLevelGetter` goes, and takes a nolint with it.** It exists only to dodge the logging→settings import cycle. With `New(Config)` the level is a Config field resolved by the caller, which is in package `cli` and can read settings directly. That also kills `//nolint:contextcheck` at config.go:78, where `GetLogLevel` is forced to use `context.TODO()` *because* it's a callback with no ctx.
- **The `//nolint:nilnil` goes.** `New` returns a real error when it can't open the file; the caller decides not to inject. No more (nil, nil) as a status channel.
- Consider having `New` take an already-resolved log **dir** rather than resolving it — that drops logging's dependency on `paths` entirely, and the `WorktreeRoot` gate already lives in `initRootLogging`.

## What must NOT break

1. **The 675 package-level `logging.Debug/Info/Warn/Error(ctx, …)` call sites.** Keep those helpers; they're the compatibility bridge and must not be migrated in this change. With no global they resolve *only* from the context — and I'd fall back to `slog.Default()` when the ctx has no logger, exactly as today. That's the runtime's global, not one we own, so the "no globals" goal still holds, and the ≤9 `context.Background()` diagnostic sites keep behaving as they do now.
2. **`WithSessionID` / session_id on redaction diagnostics** — the thing you just shipped. Verify end-to-end after, not just by unit test.
3. **`redact` keeps taking `*slog.Logger`.** It's a library package and shouldn't depend on our wrapper type.
