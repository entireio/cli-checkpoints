`piReviewTokens(env.Message.Usage)` is emitted per `message_end`, but the `Tokens` event contract is cumulative running totals that the consumer *overwrites* (`run.go`: `tokens = e // overwrite`). Pi's per-message `usage` is not cumulative — its own transcript fixtures show `output` going `50 → 30` (and `50 → 60 → 40`) across messages — so for any multi-message review (every review that calls tools) the final reported tokens reflect only the last assistant message, undercounting total `output` (and `input`). Accumulate output across messages (cf. gemini's `CalculateTokenUsage` which sums `usage.OutputTokens += msg.Tokens.Output`) instead of relying on overwrite.
