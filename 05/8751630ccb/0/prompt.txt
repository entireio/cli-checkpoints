**SliceFromLine Implementation** (`transcript/parse.go` lines 110-143):
```go
// Returns the content starting from line number `startLine` (0-indexed).
// This is used to extract only the checkpoint-specific portion of a cumulative transcript.
func SliceFromLine(content []byte, startLine int) []byte {
    if len(content) == 0 || startLine &lt;= 0 {
        return content  // startLine=0 → return full
    }
    // Find byte offset of startLine's beginning
    lineCount := 0
    offset := 0
    for i, b := range content {
        if b == '\n' {
            lineCount++
            if lineCount == startLine {
                offset = i + 1
                break
            }
        }
    }
    if lineCount &lt; startLine {
        return nil
    }
    return content[offset:]  // Return from startLine to EOF
}
```

### Checkpoint Sharing vs. Duplication

**Per Checkpoint, Per Session**:
- Each `&lt;checkpoint_id&gt;/&lt;session_num&gt;/` subdirectory gets its OWN `full.jsonl` 
- Multiple sessions in one checkpoint → multiple full.jsonl files (one per session)
- **Duplication is INTENTIONAL**: Each checkpoint is self-contained (readable without other checkpoints)

**Content Deduplication**:
- Git object store deduplicates identical blobs via content hashing
- `content_hash.txt` stores sha256 of full transcript (line 813: `fmt.Sprintf("sha256:%x", sha256.Sum256(transcriptBytes))`)
- If two checkpoints have identical transcript ranges, git packs them once

## Final Answer

| Aspect | full.jsonl | transcript.jsonl |
|--------|-----------|------------------|
| **Stores** | FULL session transcript | SCOPED to checkpoint (delta) |
| **Start Position** | Fixed (line 0) | Via `CheckpointTranscriptStart` |
| **Per Checkpoint** | Full copy | Slice from start offset to end |
| **Example** | Lines 0-999 stored as-is | If `CheckpointTranscriptStart=750`, only lines 750-999 |
| **Optional** | Always written | Best-effort, can be skipped |
| **Purpose** | Source-of-truth for rewind/resume | Efficient, normalized viewing |

**Both formats use the SAME underlying data** — `full.jsonl` stores it completely, `transcript.jsonl` stores a pre-sliced, pre-compacted view. Neither is a delta; both are complete within their scope (full or scoped). The `CheckpointTranscriptStart` line offset is the pivot point for scoping.</result>
