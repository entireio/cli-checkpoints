## 2. `gitremote.GetRemoteURL` / `GetPushURLs`

gitremote.go:97-109:
```go

func GetRemoteURLInDir(ctx context.Context, dir, remoteName string) (string, error) {
	cmd := exec.CommandContext(ctx, "git", "remote", "get-url", remoteName)
	if dir != "" { cmd.Dir = dir }
	output, err := cmd.Output()
	if err != nil { return "", fmt.Errorf("remote %q not found", remoteName) }
	return strings.TrimSpace(string(output)), nil
}
```
That is the FETCH URL (`remote.&lt;name&gt;.url`), first entry only.

gitremote.go:111-137:
```go
func GetPushURLs(ctx context.Context, remoteName string) ([]string, error) {
	cmd := exec.CommandContext(ctx, "git", "remote", "get-url", "--push", "--all", remoteName)
	output, err := cmd.Output()
	if err != nil { return nil, fmt.Errorf("remote %q not found", remoteName) }
	var urls []string
	for _, line := range strings.Split(string(output), "\n") {
		if trimmed := strings.TrimSpace(line); trimmed != "" { urls = append(urls, trimmed) }
	}
	if len(urls) == 0 { return nil, fmt.Errorf("remote %q has no push URL", remoteName) }
	return urls, nil
}
```
Its doc comment (gitremote.go:111-119) states the semantics explicitly: push destinations are `remote.&lt;name&gt;.pushurl` when any is set and `remote.&lt;name&gt;.url` otherwise (git's `push_url_of_remote`), all of them, in config order. `git remote -v`'s `(push)` lines are produced by the same `push_url_of_remote` rule, in the same config order — so yes, same set and same order for the same remote. `remote_topology.go:131-152` (`pushURLsByRemote`) relies on exactly that equivalence, and its own comment says so: "it already applies git's pushurl-replaces-url rule and lists every push URL in order". No `dir` variant exists for `GetPushURLs` (it is cwd-only).
