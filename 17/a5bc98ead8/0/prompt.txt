## SUMMARY

This is a clean, security-conscious implementation. The credential/host safety — the highest-risk area — is sound: the synthesized clone URL is `entire://&lt;host&gt;/gh/&lt;owner&gt;/&lt;repo&gt;` with **no credential embedded** (token exchange happens later inside `git-remote-entire`, which only sends credentials to a host whose `/.well-known` advertises a core trusted by an existing local context, failing closed otherwise). Both the user-supplied `--cluster` and the server-provided `chosen.ClusterHost` pass through the allow-list/format validator `validateClusterHost` **before** any URL is built or any credentialed request is made, and that validator specifically defeats the `cluster@evil.com` userinfo-demotion attack with a round-trip-to-bare-host check plus DNS-label/IP validation. `git clone` is invoked via exec argv (not `sh -c`), owner/repo/host are charset-restricted at the boundary (closing `?`, `#`, `..`, control chars), and no token is logged or printed. Multi-cluster handling correctly uses `NewAccessibleForm`, gates on `interactive.CanPromptInteractively()`, and fails fast with a `--cluster` pointer when non-interactive; cross-cluster routing correctly uses `coreapi.NewForCluster`. **Overall: approve** (one missing `--` separator before positional args is the only finding I'd want addressed; the rest are nits/scope).

## MEDIUM+ FINDINGS

### MEDIUM — Missing `--` separator before positional args in `git clone` invocation
**File:** `cmd/entire/cli/repo_clone.go` (~`runGitClone`, line ~270)

```go
args := []string{"clone", cloneURL}
if targetDir != "" {
    args = append(args, targetDir)
}
gitCmd := exec.CommandContext(ctx, "git", args...)
```

There is no `--` separator inserted before the positional arguments, so an argument that begins with `-` could be interpreted by `git clone` as a flag rather than a positional (argument injection). For the synthesized-URL path this is closed off because `cloneURL` always starts with `entire://`, but two vectors remain reachable: (1) the full-`entire://`-passthrough path trims but never re-validates that `ref` still starts with `entire://` after trimming — actually it does (`isEntireCloneURL` is checked), so `cloneURL` is safe there too; (2) **`targetDir` (`args[1]`) is entirely user-controlled and never validated** — a user running `entire clone /gh/a/b -- --upload-pack=...` or `entire clone /gh/a/b --foo` would pass `--foo` as `git clone`'s second positional, and git would treat it as an option. Insert a `--` before the positionals: `args := []string{"clone", "--", cloneURL}` (and `targetDir` after it). This is defense-in-depth — cobra captures `--cluster`/`--json` before they reach `args[1]`, so practical exploitability is low — but the `--` is the standard, cheap fix and matches the security posture of the rest of this change.

## LOW NITS

- **`entire://` passthrough does not call `validateClusterHost`** (`repo_clone.go`, `isEntireCloneURL` branch). This is *safe* — `git-remote-entire` resolves the host via `clusterdiscovery.ResolveContextForCluster`/`ResolveClusterCores`, which fails closed for any host without a matching trusted local context — but a one-line comment noting "host safety for this path is enforced downstream in git-remote-entire" would save the next reader the same trace I just did. (The shorthand path's comment is excellent; this path is silent.)

- **`validateClusterHost` does not validate the port component.** `url.Parse("https://"+host)` with `u.Host == host` allows `host:port`; `u.Hostname()` strips the port before label validation, so a value like `cluster.entire.io:notaport` round-trips (`u.Host == host` holds, `Hostname()` returns the host, labels pass). `url.Parse` rejects clearly-malformed ports, and a bad port only breaks the user's own clone, so this is cosmetic — not a credential-leak vector. Worth a sentence in the doc comment if you want to be precise.

- **Test coverage gap: no test for the full-`entire://`-passthrough RunE path** (that `--cluster` is ignored and the URL is forwarded verbatim). `TestIsEntireCloneURL` covers the predicate, but not that `runGitClone` receives the untouched URL.
