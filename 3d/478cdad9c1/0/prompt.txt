## Findings

**REQUIRED - High Severity:**

**File:** cmd/entire/cli/resume.go
**Line:** 902-905
**Issue:** Unsupported checkpoint version errors from `RestoreLogsOnly` are not detected and are instead treated as non-fatal errors that trigger a fallback to `resumeSingleSession`.

```go
sessions, restoreErr := strat.RestoreLogsOnly(ctx, w, errW, point, force)
if restoreErr != nil || len(sessions) == 0 {
    // Fall back to single-session restore (e.g., old checkpoints without agent metadata)
    return resumeSingleSession(ctx, w, errW, ag, sessionID, checkpointID, repoRoot, force)
}
```

When `RestoreLogsOnly` returns an `unsupportedVersionError` (wrapped in `fmt.Errorf`), the code falls back to `resumeSingleSession`. However, unsupported checkpoint versions should fail fast with a clear error, not silently fall back. All other read commands (explain, rewind, explain_export) correctly detect and return unsupported version errors immediately.

**Consequence:** Users attempting to resume a multi-session checkpoint with an unsupported version will fall back to the single-session restore path, which may mask the actual problem (unsupported checkpoint version) with a different error from `resumeSingleSession`.

**Fix:** Add an unsupported version check before falling back:
```go
sessions, restoreErr := strat.RestoreLogsOnly(ctx, w, errW, point, force)
if restoreErr != nil {
    if checkpointpolicy.IsUnsupportedVersion(restoreErr) {
        return restoreErr
    }
    if len(sessions) == 0 {
        // Fall back to single-session restore...
        return resumeSingleSession(...)
    }
}
```

### 1. Redundant Checkpoint Reads in Two Call Sites

**Files:** `cmd/entire/cli/resume.go` (line 970-976) and `cmd/entire/cli/rewind.go` (line 732-740)

**Problem:** Both `resumeSingleSession()` and `restoreSessionTranscriptFromStrategy()` call `checkpoint.ReadCheckpoint()` followed by `checkpoint.ReadRawSessionLogForCheckpoint()`. The second function internally calls `ReadCheckpoint()` again (see `api/checkpoint/interfaces.go:125`), resulting in duplicate reads of the checkpoint metadata from storage.

**Example - resumeSingleSession:**
```go
summary, err := checkpoint.ReadCheckpoint(ctx, stores.Persistent, checkpointID)  // Read 1
if err == nil {
    err = checkpointpolicy.EnsureCanReadVersion(checkpointID.String(), summary.CheckpointVersion)
}
if err == nil {
    logContent, _, err = checkpoint.ReadRawSessionLogForCheckpoint(ctx, stores.Persistent, checkpointID)  // Calls ReadCheckpoint again internally
}
```

**Suggested Simplification:** Move the version check into a helper that integrates with the read logic, or skip the separate `ReadCheckpoint()` call and extract the version check into the error handling path after `ReadRawSessionLogForCheckpoint()` returns. The version is available in the summary returned by `ReadRawSessionLogForCheckpoint()` (via its internal `ReadCheckpoint()` call), though extracting it would require refactoring the API.

**Impact:** Does not break behavior. Only affects storage I/O efficiency. The error handling and control flow remain correct since both versions of the checkpoint are identical.
