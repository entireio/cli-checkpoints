## 3. Ordering, grouping, count/pagination

- **Ordering (server):** `listSessionsForUser` orders `ORDER BY rs.last_activity_at DESC, rs.session_id ASC` — newest lastActivityAt first. Authorship filter: `first_commit_author_username = &lt;github login&gt;`; window filtered on `last_activity_at` between start/end of timeframe.
- **Grouping (client):** `groupByDay` buckets sessions by the **local calendar day of `lastActivityAt`** (`toLocalDateString`; null → "unknown"). Day groups are sorted by date **descending**. Within a day, sessions keep the API order (i.e. lastActivityAt desc, preserved via `_index`).
- **Section header per day:** `formatDisplayDate(date)` renders as `en-GB` "Weekday, D Mon" (e.g. "Monday, 6 Jul"); "unknown" → "Unknown Date". Header also shows a count: `"{n} session"` / `"{n} sessions"`.
- **Count / pagination:** No pagination and no "load more". The overview fetches at most `USER_OVERVIEW_RECENT_SESSIONS_LIMIT = 50` (server hard-caps at 1000). All fetched sessions are rendered. Empty state: a FloatingShell reading "No activity in this timeframe".

## 4. displayName vs customName, and the timeframe selector

- **Row title uses `displayName` only.** The choice between customName and other names is made **server-side** in `resolveSessionName` (`sessions.ts` line 471): `custom_name?.trim() || generated_name?.trim() || display_name`. So precedence is customName → AI generated_name → heuristic display_name. `customName` is also returned raw in the envelope (so a client can detect/clear an override), but the overview row does not use it — it just renders `displayName`, then truncates to 120 chars.
- **Timeframe selector:** None on the overview page. `useUserDashboardData("last-month", …)` is hardcoded to `"last-month"`; there is no `useState`/selector for timeframe and no pagination controls in `OverviewPage.tsx` or `RecentSessionsList.tsx`.

## 5. What else the page shows (from related data)

Everything else on the Overview page comes from the **checkpoints** endpoint (`/api/v1/cache/user/checkpoints?timeframe=last-month`), not from `/me/sessions`. In `OverviewPage.tsx`, below a greeting header ("Morning/Afternoon/Evening, {firstName}" + "Here's an overview of your recent activity."):
- `&lt;StatsGrid stats={stats} /&gt;` — computed stats: tasks (checkpoint count), orchestration, iteration, throughput, continuity (hours + current/longest streak). See `computeStats` in the hook.
- `&lt;ContributionsSection chartData hourlyChartData totalCheckpoints={stats.tasks} /&gt;` — the contribution charts / heatmap (daily `chartData` and hourly `hourlyChartData`), built from checkpoints in `computeChartData`/`computeHourlyChartData`. Files: `.../users/components/ContributionsSection.tsx`, `ContributionChart.tsx`.
- `&lt;CheckpointsByRepo data={repoData} maxRepos={5} /&gt;` — top 5 repos by checkpoint count (`computeRepoData`). File: `.../users/components/CheckpointsByRepo.tsx`.
- Onboarding/empty branch: if the user has no checkpoints, the page shows `CliInstallationSteps` instead of the dashboard; while loading it shows `OverviewSkeleton` / `SessionsListSkeleton`.
