1. entire:// passthrough skips validateClusterHost (repo_clone.go, isEntireCloneURL branch)
The shorthand path validates the host on both the --cluster flag and the server-supplied chosen.ClusterHost (nice defense-in-depth, with a clear comment about the host@evil.com STS-audience token-leak vector). But a user-supplied full entire://<host>/gh/... URL is passed verbatim to git clone with no host validation. The same token-leak rationale the PR cites applies — entire://realcluster@evil.com/gh/... would sail through. It's arguably no worse than a raw git clone entire://…, so not critical, but it's inconsistent with the PR's own stated guard. Consider parsing the host out and running it through validateClusterHost.

I _don't_ want any fixes for this, i WANT the url as the user typed it passed through to `git` cli.  however, if there's a misleading comment or doc, we should fix that.
