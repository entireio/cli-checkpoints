## Verification results — PR #1498, head of `origin/feat/control-plane-friendly-names`

All three findings target `cmd/entire/cli/resolveref.go`, which was refactored away from the original "server filter + client re-filter" design into a server-side singular-match lookup. Verdicts below.

### F1 [medium] — Case-sensitivity mismatch between server filter and client picker → **ADDRESSED**

The redundant client-side re-filter that the finding flagged is gone entirely. The resolvers no longer call a `pickOrg`/`pickProject` helper that re-checks `p.Name == name`; those helpers no longer exist anywhere in `cmd/entire/cli/` (grep confirms zero matches). Instead the server now returns the single match under a singular `org`/`project` response field, and the resolver just unwraps it:

- `resolveOrgRef` (lines 59-70): `out, err := c.ListOrgs(... Name: ...)` then `org, ok := out.Org.Get()` — returns `org.ID` with no name comparison.
- `resolveProjectRef` (lines 118-129): same shape via `out.Project.Get()`.

Because there is no client-side string comparison at all, the case-sensitivity mismatch cannot occur — a server case-insensitive match flows straight through. The doc comment (lines 17-21) explicitly documents the new contract: "case-insensitive by-name lookup … the CLI never lists everything and filters client-side." Note this is a fix-by-redesign rather than the suggested `strings.EqualFold` patch, but it fully closes the issue (it's actually stronger, since no client filter remains to diverge).

---

### F2 [medium] — `resolveAccountRef` forwards empty `AccountId` → **ADDRESSED**

The exact empty-AccountId guard suggested in the finding is present, with an explanatory comment matching the failure mode described:

```go
// resolveref.go:89-94
// ResolvedIdentity.AccountId is a plain string, so a handle that resolves to
// an identity with no backing account would silently forward "" as the owner
// ULID and fail later with an opaque server-side create error. Catch it here.
if id.AccountId == "" {
    return "", fmt.Errorf("handle %q resolved to no account", ref)
}
return id.AccountId, nil
```

This returns a clear local error before the empty string can reach `CreateProjectInputBody.OwnerId`, exactly as recommended.
