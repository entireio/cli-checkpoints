## MEDIUM+ FINDINGS

**[MEDIUM] Cache-replay percentage mixes top-level numerator with subagent-inclusive denominator** — `cmd/entire/cli/session_tokens.go`, ~line 248 (`recommendationRules`, `cacheReadPercent := tokenPercent(signals.Tokens.CacheRead, signals.Tokens.Total)`).
`signals.Tokens.Total` is computed by `totalTokens()`/`buildSessionTokensUsage`, which **includes** subagent tokens recursively, but `signals.Tokens.CacheRead` is only the top-level `usage.CacheReadTokens` (subagent cache reads are not surfaced in `sessionTokensUsage`). When a session has meaningful subagent token volume, the denominator is inflated relative to the numerator, so `cacheReadPercent` is systematically understated and the "context-replay-hotspot" (and the dependent `summarize-before-boundary`) recommendation can fail to fire even when top-level cache replay genuinely dominates the top-level call. The displayed cache-read figure in the recommendation message (`Cache/context replay is X% of token volume`) will also under-report. Consider computing the percentage against a top-level-only total (input+cacheCreation+cacheRead+output) or otherwise aligning numerator and denominator scope.
