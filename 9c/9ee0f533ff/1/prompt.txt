### **FINDING 1: Offset Computation at Wrong Depth**

**Location:** `/Users/ninawork/entire/devenv/cli/cmd/entire/cli/checkpoint/committed.go`, lines 943–969 (`compactStartOffset` function)

**Issue:** The offset is computed **outside** the `transcript/compact` package by calling `Compact` twice (full + scoped) and subtracting line counts. This duplicates the compaction work and fragments the offset computation from the actual slicing logic.

**Why it's fragile:**
- **Implicit assumption:** The code assumes checkpoint boundaries fall on user-prompt boundaries, so `full[offset:] == scoped` after compaction. This is stated in a comment (line 947–948) but is never enforced by the package.
- **Duplicated compaction:** Every write path calls `Compact(full, StartLine=0)` then `Compact(full, StartLine=startLine)` separately. If future changes to `Compact` merge/drop lines differently at boundary detection or alter how `StartLine` is handled, the subtraction will diverge.
- **Unmapped line counts:** `countLines()` counts newlines; if `Compact` ever adds/removes trailing newlines or changes its output format (e.g., a future agent adds JSON arrays), the count won't match the slice.
- **No type safety:** The offset is raw `int`; there's no checkpoint-scoped type that proves the offset came from the right portion of the file.

**What the current implementation does:**
```go
fullCompacted := Compact(transcript, StartLine: 0)              // Full output
scoped := Compact(transcript, StartLine: startLine)             // Scoped output
offset := countLines(fullCompacted) - countLines(scoped)        // Line subtraction
```

**More robust approach:** The offset computation should happen **inside** `transcript/compact/compact.go` as a new return value. `Compact` already knows:
1. How many lines it output for the full transcript
2. How many lines it output for the scoped transcript  
3. The exact slicing boundary (where `scoped` began in `full`)

Returning `(compactedOutput []byte, compactStartOffset int, error)` from `Compact` avoids:
- Calling `Compact` twice per checkpoint
- Recomputing the offset outside the slicing logic
- Assuming boundary semantics without enforcing them
- Fragility to future `Compact` changes
