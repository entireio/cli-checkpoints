## SUMMARY

This PR's in-scope delta is solid and, notably, **reduces** the security surface rather than expanding it. The headline probe refactor replaces a data-plane smart-HTTP `info/refs` poll — which minted short-lived repo-scoped pull tokens, carried them in redirect `Location` userinfo, and needed `checkProbeRedirect` to keep them inside the cluster trust domain — with a single authenticated control-plane `GetMirror` status poll per tick. That eliminates the token-in-URL/redirect-leak vector entirely and is gated by a new `Mirror.status` enum that the spec, generated code (schema/validator/decoder/JSON), and consuming code all agree on; the generated delta is a clean ogen regeneration with no hand-edits. The new `entire auth token` command reuses the existing `resolveAuthStatusTarget`, which already applies the env-token-first precedence and never re-resolves via the buggy `auth.ResolveControlPlaneTarget`, and it prints the bearer only to stdout (errors/hints to stderr, no `logging.*` calls) so secrets aren't logged. Tests are real (scripted fake `GetMirror`, exhaustive status coverage, correct not-parallel annotations on the two tests that mutate package/env state). I found **no medium-or-higher issues** — only minor nits. Overall judgment: **APPROVE.**

## MEDIUM+ FINDINGS

None.

I specifically checked the highest-risk items and they are clean:
- **No token logging/printing leak.** `auth token` writes only `target.token` to `cmd.OutOrStdout()`; the not-logged-in hint and all errors go to `cmd.ErrOrStderr()`. No `logging.*` call touches the token. It enforces `RequireSecureURL` before emitting a bearer for a non-`--insecure` core, mirroring `auth status`.
- **No credential-bearing mirror URL echoed.** The refactor removed the only place a pull token entered a URL (the data-plane probe + its redirect chain).
- **Core resolution is correct for display.** Resolution flows through `resolveAuthStatusTarget` (env-token-first), not `auth.ResolveControlPlaneTarget`.
- **Probe behavior preserved/improved.** First poll is immediate; `processing` keeps waiting; `ready`/`failed`/`suspended` are terminal; transient `GetMirror` errors are tolerated up to `maxConsecutivePollErrors` then surfaced; ctx cancel → SilentError, deadline → timeout error. The empty/absent-status case correctly keeps polling to the deadline.
- **Spec coherence.** `Mirror.status` enum (`processing|ready|failed|suspended`) added to spec; generated `MirrorStatus` const set, `OptMirrorStatus`, `Validate()`, and `decodeGetMirrorResponse` all match; no generated file hand-edited.

## LOW NITS

- **`cmd/entire/cli/auth_token_test.go` ~52** — The "not logged in" subtest relies on the empty-`contexts.json` early return in `resolveStatusTarget` to avoid ever calling the keychain, rather than explicitly installing the file token backend (`tokenstore.UseFileBackendForTesting`) or `keyring.MockInit`. It's safe today (and the in-process `testdirs` net covers it), but a future change that makes the not-logged-in path consult the keychain before checking contexts would silently start touching the dev's real keychain. Consider adding the file-backend setup defensively, matching the pattern other auth tests use.

Minor wording imprecision; not a behavior bug since the command has no cluster flag.
