## MEDIUM+ FINDINGS

**[Medium] cmd/entire/cli/review/cmd.go ~304 &amp; ~325 (also profile.go:431)** — `--configure` always steals the default profile. Both the scripted path (`saveReviewProfile(ctx, profileName, profile, true, scope)`, line 304) and the interactive path (line 325) pass `makeDefault=true` unconditionally, and `saveReviewProfile` then does `if makeDefault || defaultName == "" { defaultName = profileName }`. This means editing any secondary profile — e.g. `entire review --configure security --set-agents codex` when `general` was the user's default — silently rewrites `review_default_profile` to `security`. There is no flag to opt out, and with `--local` it writes the new default into `settings.local.json`, which then overrides the project default for that developer. The default should only change on first creation (the `defaultName == ""` case already handles that) or via an explicit `--set-default`/`--make-default` flag. Recommend passing `false` from the edit paths, or gating `makeDefault` behind an explicit flag.

**[Low-Medium] cmd/entire/cli/review/cmd.go ~623-637** — `--set-model agent=` (empty model) silently clears the model rather than erroring. `strings.Cut("claude-code=", "=")` returns key=`claude-code`, model=``, ok=`true`, so the malformed-spec guard (`!ok || key == ""`) passes and the worker's model is set to empty string. This is inconsistent with the stricter handling elsewhere and may surprise a user who fat-fingers the value expecting an error. Either reject an empty model explicitly or document that `agent=` resets to the agent default. Minor because the resulting state (default model) is still valid.
