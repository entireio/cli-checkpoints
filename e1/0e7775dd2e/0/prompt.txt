## MEDIUM+ FINDINGS

**MEDIUM — `cmd/entire/cli/session_tokens.go` (~line 122, `runSessionTokens`; flag defined ~line 110)**
The `--current` flag is a no-op. `runSessionTokens` branches `if sessionID == "" || current { sessionID = strategy.FindMostRecentSession(ctx) }`, and `FindMostRecentSession` already scopes to the current worktree unconditionally (and only falls back to all worktrees when nothing matches). So `entire session tokens` with no args and `entire session tokens --current` execute the identical code path. The flag's help text ("Prefer the current worktree's most recent session") promises a distinct behavior that doesn't exist, and `--current` cannot actually force worktree scoping or override the fallback. Either remove the flag or make it change `FindMostRecentSession`'s fallback behavior.

**MEDIUM — `cmd/entire/cli/tokens_profile.go` (`tokensProfileCheckpointUsage`, ~line 200) vs `cmd/entire/cli/checkpoint_tokens.go` (`buildCheckpointTokensReport`, ~line 250)**
The two commands disagree on token totals for a checkpoint with partially unreadable session metadata. `tokens profile` prefers the root `summary.TokenUsage` whenever `metadataReadWarning` is true (`if !metadataReadWarning &amp;&amp; sessionUsage != nil { return sessionUsage }` ... `if summary.TokenUsage != nil { return summary.TokenUsage }`), whereas `checkpoint tokens` always prefers the per-session aggregate and only falls back to `summary.TokenUsage` when the aggregate is nil (`usage := aggregateCheckpointTokenUsage(metas); if usage == nil &amp;&amp; summary != nil { usage = summary.TokenUsage }`), ignoring warnings. For the same checkpoint, `checkpoint tokens &lt;id&gt;` can therefore report a partial per-session sum while `tokens profile` reports the complete root total. Pick one precedence rule and share it so the two commands can't diverge.
