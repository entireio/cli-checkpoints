defaultPromptOnSigningFailure only checks CanPromptInteractively(), which can be true even when stderr is not a terminal (e.g., hook output redirected/piped while a controlling /dev/tty exists). In that case the prompt is written to a non-TTY writer and the hook can hang waiting for input the user never sees. Gate prompting on the actual stderr writer being a terminal, consistent with the non-TTY behavior described in the comment.
